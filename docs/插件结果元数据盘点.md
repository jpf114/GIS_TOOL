# 插件结果元数据盘点

> 更新日期：2026-05-24  
> 对照：`src/framework/include/gis/framework/result_display.h` 中 `ResultMetadataKeys` 与 `standardMetadataKeyOrder()`

## 标准优先键（展示层固定顺序）

| 键 | 含义 | 建议写入方 |
|----|------|------------|
| `action` | 动作名 | 各插件 execute 入口 |
| `input` / `output` | 主输入输出路径 | 栅格/矢量主链 |
| `band` | 波段（1-based 字符串） | 栅格类 |
| `crs` / `epsg` / `actual_srs` | 坐标系 | projection、reproject |
| `width` / `height` / `output_width` / `output_height` | 尺寸 | 栅格 info、裁切 |
| `data_type` | GDAL 数据类型 | 栅格输出 |
| `feature_count` | 要素数 | vector 主链 |
| `elapsed_ms` | 耗时 | 框架或插件 |
| `__summary__` | 人类可读摘要（单独展示） | GUI/CLI 组装 |

## 插件差异摘要

### projection

- 已写：`width`、`height`、`bands`、`wkt`（info）；`src_x/y`、`dst_x/y`（transform）
- 待对齐：info 侧 `wkt` 可映射展示为 `crs`；`bands` 暂无标准键（保留扩展字段）

### vector

- 普遍使用：`feature_count`、`skipped_count`、`source_count`、`issue_count`、`scanned_count` 等
- 检查类动作：`issue_count` + `scanned_count`（dangling_endpoint、topology 等）
- 待对齐：主链 `convert`/`buffer` 等可补充 `action`、`input`、`output`（与 CLI 一致）

### 栅格类插件（processing / terrain / spindex 等）

- 多数通过 `writeProcessingMetadata()` 写入 GeoTIFF 侧车信息
- `result.metadata` 字段因动作而异，发布前以 real_*_regression 摘要为准

## 后续收口建议（任务 2-2 / 2-5）

1. vector / projection 主链成功结果统一 `mergeResultMetadata` 写入 `action`、`input`、`output`
2. 检查类 CSV/GPKG 输出保留 `issue_count` 等领域键，不强行改名
3. real regression 断言优先：`output` 存在、尺寸/类型、`feature_count` 或 `issue_count` 范围
