# 交付自验（目标机一页）

> 适用对象：只拿到 `cmake --install` 交付目录（或下面第 4 节那个 zip）的机器。
> **前提**：Windows 10/11 x64。批次 C C17（拍板 2）之后 **不需要**再自装 VC++ Redistributable，
> 也不需要装过 Visual Studio。若你的包是 C17 之前打的，请先看第 3 节的运行库一项。
> 本仓不做安装包、不走云端构建，交付形态就是这份目录（见 `docs/RELEASE.md` 的"交付方式"）。

## 1. 三条命令判包是好的

在包根目录打开 PowerShell（`powershell.exe` 5.1 或 7 都行），把 `.\` 当作包根。
三条全过 ⇒ 这个包可用；任何一条不过 ⇒ 按第 3 节对照表定位。

### ① 插件枚举：数量与内容

```powershell
chcp 65001 > $null                    # 让中文插件说明正常显示（5.1 默认 GBK 码页会把中文打成乱码）
$out = & .\bin\gis-cli.exe --list
"rc=$LASTEXITCODE  行数=$($out.Count)  插件行=$(@($out | Select-String '^  [a-z_]+ - ').Count)"
```

期望：`rc=0`、**插件行 = 13**、总行数在同一版本内固定（本机现测 27 行 / 1852 字节）。
`rc=0` 但插件行少于 13 ⇒ 有插件没被加载，看第 3 节第 2 行。

### ② 真跑一条动作（读你自己的数据，不依赖本仓的 data/）

```powershell
& .\bin\gis-cli.exe --list                      # 先确认 vector 在列
& .\bin\gis-cli.exe vector info --input "D:\你的数据\某图层.shp" --output "$env:TEMP\自验.txt"
"rc=$LASTEXITCODE"
```

期望：`Success:` 开头、打出图层要素数/字段表、`rc=0`。
栅格同理：`.\bin\gis-cli.exe raster_inspect info --input "D:\你的数据\某图.tif"`。

⚠ 矢量侧的 `--output` 目前**必须给**（插件级把 `output` 标成必填，本仓漂移清单记为 D1，待放开）。
`vector info` 本身不写这个文件，给个临时路径即可。

### ③ 坐标转换（这一条才真正会用到 PROJ 数据，等于验证"数据随包"）

```powershell
& .\bin\gis-cli.exe projection reproject --input "D:\你的数据\某图.tif" `
    --output "$env:TEMP\自验_4326.tif" --dst_srs EPSG:4326
"rc=$LASTEXITCODE  产物=$((Get-Item "$env:TEMP\自验_4326.tif" -ErrorAction SilentlyContinue).Length) B"
```

期望：`rc=0` 且产物字节数 > 0。出现 `Cannot find proj.db` ⇒ 见第 3 节第 3 行。

## 2. 一条可选的 GUI 自检

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
$env:GIS_TOOL_SETTINGS_INI = "$env:TEMP\自验_settings.ini"
$env:GIS_CUSTOM_INDEX_PRESET_FILE = "$env:TEMP\自验_presets.json"
& .\bin\gis-gui.exe --self-test; "rc=$LASTEXITCODE"
```

期望 `rc=0`。后两个环境变量是**守卫要求**的（本仓 N101/N102：不指定落点时 `--self-test` 直接 `rc=3`，
那是"不许对真实用户配置动手"的保护，不是 GUI 坏了）。不带 `QT_QPA_PLATFORM=offscreen` 的机器上
如果没有显示子系统，GUI 起不来属正常。

## 3. 失败对照表

| 现象 | 结论 | 处置 |
|---|---|---|
| 双击/命令行启动 exe 直接 `0xC0000135`（`STATUS_DLL_NOT_FOUND`） | 缺 VC++ 运行库 | C17 之后的包里 `bin/` 应自带 `msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll`、`concrt140.dll` 等 **8 件**。一件都没有 ⇒ 你拿到的是 C17 之前的包，或拷贝时漏了 `bin/*.dll`；要么补装 VC++ Redistributable，要么重新取包 |
| `--list` 的 `rc=0` 但插件行数少于 13 | 某个插件 DLL 没加载 | 看 `bin/plugins/` 是否齐 13 个 `plugin_*.dll`；缺哪个 ⇒ 对应功能整块不可用，重新取包 |
| `Cannot find proj.db` / `Invalid SRS for -t_srs` | `share/proj/` 丢了或没跟着包走 | 交付目录必须整棵树拷，不能只拷 `bin/`：`gis-cli`/`gis-gui` 从 exe 目录向上找 `share/proj`、`share/gdal`、`plugins` |
| 中文说明在控制台是乱码，但 `rc=0` 且产物正常 | 只是码页问题，不是包坏 | `chcp 65001` 后再看；判据以 `rc` 和产物字节为准 |
| 只装到别的盘/改了目录层级后功能异常 | 相对定位被破坏 | 保持 `bin/`、`share/`、`lib/`、`include/` 的同级结构，整个目录一起移动 |

## 4. 打包与体积基线

```powershell
Compress-Archive -Path .\bin, .\share, .\lib, .\include -DestinationPath ..\GIS_TOOL.zip -Force
```

本机同一棵 Release 构建树现测（C17 之后）：**437 个文件 / 约 193 MB**。
明显小于这个数 ⇒ 大概率是 `bin/` 里的运行库或 `share/` 数据没拷全；大很多 ⇒ 可能把
`install/` 的旧副本一起打了（本仓有过"同一文件两份副本"多占 167 MB 的前科）。

## 5. 这套自验覆盖不到什么（如实说明）

- **没有在"从没装过 VC++ Redistributable 的干净机器"上做过端到端验证**。
  开发机能给的替代判据是这两条，且都已落成 ctest 用例：
  `install_closure`（包内每个 PE 的每条直接导入，要么在包内、要么是白名单里的 OS 组件）与
  `install_smoke`（把环境剥到只剩包自身 + Windows 目录后，上面 1、2、3 三条 + GUI 自检全过，
  外加"藏掉包内 `share/proj` 后坐标转换必须失败"的反臂）。
- GUI 的**业务行为**不在这里判（批次 C 明确 GUI 深验证延后），这里只判它起不起来。
- 代码签名未配置：SmartScreen 仍可能提示"未知发布者"，那是签名问题，不代表包坏。
