# 影像处理与分析 / 全色锐化

## 功能说明

将多光谱影像与全色影像融合，输出更高空间分辨率的多波段结果。

## 输入与输出

- 输入：
  - 输入文件：多光谱影像
  - 全色影像：单波段高分辨率影像
- 输出：融合后的多波段栅格，建议 `.tif`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 多光谱影像。 |
| 输出文件 | 文件路径 | 是 | 无 | 输出融合结果。 |
| 全色文件 | 文件路径 | 是 | 无 | 全色影像路径。 |
| 融合方法 | 枚举 | 否 | `brovey` | `brovey` `mean_blend` `ihs`。 |

## 算法内容

全色锐化用于把高空间分辨率的全色影像与较低分辨率的多光谱影像融合，得到兼顾空间细节和多波段信息的输出结果。当前实现支持 `brovey`、`mean_blend` 和 `ihs` 三种方式，并在必要时先把多光谱重采样到全色分辨率。

## 处理流程

1. 打开多光谱影像和全色影像。
2. 检查多光谱波段数是否满足当前方法要求。
3. 读取全色波段和多光谱全部波段，并统一转为浮点格式。
4. 如果多光谱尺寸与全色不一致，则先把多光谱重采样到全色分辨率。
5. 按所选方法执行融合：
6. `brovey`：先求多光谱平均强度，再按各波段与平均强度的比值乘上全色。
7. `mean_blend`：各多光谱波段与全色直接做均值混合，**逐像元 `(MS + PAN) / 2`**，不注入全色细节（旧名 `simple_mean` 已废弃，传入会被显式拒绝）。
   口径与实测对上的部分是那个 `/2`：批次 D Task 15 的变异取证把 `sharp = sharp * 0.5` 删掉后，常量夹具
   （MS band1≡40、PAN≡100）的产物从 70 变成 140，用例 `PansharpenMeanBlendReplacesSimpleMean` 当场红
   ⇒ "均值"而不是"求和"这件事是被钉住的，不是靠名字推断的。
8. `ihs`：**并不做颜色空间转换**（代码里没有 HSV/RGB 变换）：按 `intensity = (r+g+b)/3` 求亮度，把 `|intensity| < 1e-10` 的像元垫成 `1e-10`，取 `ratio = pan / intensity`，再把**同一比例直接乘回 r/g/b**；第 4 个及以后的波段原样透传。
9. 将融合后的各波段写出为新的多波段栅格。

## 输出说明

- 输出结果为栅格文件。
- 建议优先使用 `.tif` 保存，便于后续在 CLI、GUI 或 GIS 软件中继续处理。

## 结果解释

- 输出结果空间分辨率与全色影像一致。
- 不同融合方法在细节增强和色彩保持上的表现不同，实际使用时应结合样例对比选择。

## 适用场景

- 遥感影像视觉增强、高分辨率专题判读和融合产品准备。

## 推荐输出文件名

- `全色锐化_result.tif`

## 注意事项

- **本动作全程不做 NoData 判断**（三个方法分支都不判）：PAN 与多光谱的 NoData 原值会被当作有效像元参与比值/均值/强度计算。写出时只把 **PAN 第 1 波段声明的 NODATA 值**复制给输出各波段（多波段共享同一个 GDAL_NODATA 标签），被污染的边界值不会被标成无效 ⇒ 带 NoData 边缘的影像请先裁到有效区。
  - "取自 PAN 而不是 MS"这句同样是实测过的，不是文档口径的复读：批次 D Task 15 把写出的参照数据集由 PAN 换成 MS 后，
    `PansharpenSharedNoDataTagFollowsPanBand1` 立刻红在 `outNoData = -9999`（MS 声明的值）对期望 `-555`（PAN 声明的值）上，
    而 PAN 未声明 NoData 那一侧也同时红（输出本该**完全不声明**，改后却继承了 MS）；输出的地理网格在同一臂下红为
    `gt[1] = 30`（MS 的像元尺寸）对期望 `15`（PAN 的）⇒ "包络/网格/无效值都跟 PAN"是一条有鉴别力的说法。
    `metadata` 里那句 `nodata_source` 的可追溯性另有独立一臂（把字面量 `pan_band1` 改成 `ms_band1` 会红），
    因为参照数据集那一个实参同时喂着地理网格与 NoData 取值，字符串契约没有别的可下手的落点。
- 输入多光谱至少要有 2 个波段。
- `ihs` 方法至少要求 3 个波段。
- 若全色与多光谱尺寸不同，代码会把多光谱重采样到全色分辨率。
- 全色与多光谱的**地理包络相对差异**超过容差（较大边长的 `1e-6`）时，会在 `metadata` 写
  `pan_ms_extent_mismatch=<相对差异>` 并把提示追加到结果消息里；**动作仍然成功**（同传感器 PAN/MS 正射后
  常有厘米到米级差异，硬失败会打断正常用法）。提示出现时请核对两幅输入的地理范围。
- 该校验有已知空白：**两侧都没有地理变换、或只有一侧有变换时都不报警** ⇒ 准确说法是"缺地理参考的输入得不到范围校验保护"。
- 产物侧的口径在批次 D Task 8（2026-10-27）变了：写出多波段结果时**只在源真取到地理变换时才把它写进产物**，取不到就不写
  ⇒ 无参考输入得到的是"**完全没有地理变换**"的产物，而不是改前那种退化成 GDAL 默认 `Origin = (0, 0) / Pixel Size = (1, 1)`
  的 GeoTIFF（GDAL 在取不到变换时仍会把默认恒等式 (0,1,0,0,0,1) 填进调用方的数组，GDAL 3.12.4 `gcore/gdaldataset.cpp:1506-1512`）。
- **动作仍然成功、产物仍然生成**（既有契约：拿不到地理变换不得当成失败，用例 `PansharpenNoGeoTransformSkipsExtentCheck` 钉住），
  范围校验的那处空白也照旧不变——本刀改的只有产物里那一段元数据。
- 融合方法 `mean_blend` 是批次 A 里由 `simple_mean` **更名**而来：旧值不再被接受，传入会走显式拒绝并给出可操作错误，
  不会被静默改名。

## 枚举值说明

### 融合方法

- `brovey`：Brovey 融合
- `mean_blend`：PAN-MS 均值混合
- `ihs`：IHS 融合
