# 影像处理与分析 / 统计信息

## 功能说明

统计指定波段的基础数值信息，并在结果面板显示。

## 输入与输出

- 输入：栅格影像
- 输出：**没有文件输出**，仅返回文本和元数据。执行成功也不会创建、覆盖或删除任何文件（连同名 `.aux.xml` 边车都不会往"输出"那个路径写）。
- ⚠ 命令行侧还有一道与上面这句话不符的必填闸：`gis-cli processing stats` 不带 `--output=` 会被拒
  （实测返回码 1、文案 `Error: 参数“输出栅格”不能为空`），带上了那个路径也照样不会出现产物（实测产物不存在）。
  原因是统计动作与 `processing` 的其余动作共用同一份参数声明，里面把"输出栅格"标成了必填，而统计本身既不读也不写它；
  图形界面按动作各自的关键字白名单只露"输入文件"和"波段号"两项，所以只有命令行能碰到这个不一致。
  该缺陷已立案 **N183**（与 vector 侧 `--output` 误报必填同族，但多出"传了也静默不写"这一半）；
  修法要改可观测行为（把该动作的必填摘掉，或让命令行的必填闸按动作可见键走），归产品拍板，文档这里只如实描述现状。

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入影像。 |
| 波段号 | 整数 | 否 | `1` | 从 1 开始。 |

## 算法内容

统计信息不是改写型算法，而是对指定波段执行一次基础数值检查。当前实现会现算该波段的最小值、最大值、均值与标准差，并读取数据类型、尺寸和 NoData 声明，以文本和元数据形式返回；四个统计量不取任何缓存，NoData 声明也只认影像自身那一份（同名边车不参与，两件事各有一条注意事项）。

### 标准差是"总体"口径，不是"样本"口径

返回的 `StdDev` / `stddev` 由 GDAL 的波段统计入口现算得到，除数是**像元总数 n**（总体标准差），
不是 `n − 1`（样本标准差）。两者在窄值域或小图上差别不小，引用这个数字时别看错一族公式：
52×12 的等差斜坡（档值 0…51）总体口径给 `sqrt((52² − 1)/12) = 15.008331`，
换成样本口径给的是 `15.020371`，差 `0.012040`。单测里就是拿这两个数把口径钉住的
（见 `tests/test_plugins.cpp` 的 `ProcessingStatsExecution` 用例与 `tests/action_gold_cases.txt` 的 `processing,stats` 行）。

四个统计量每次都重读像元：同名 `.aux.xml` 边车里缓存的旧统计**不会**被这个动作取用（实测改边车里的缓存值再跑，
返回的仍是现算结果；那份边车只会被写回），`raster_inspect` 的逐波段信息那条入口是同一形态。
**这两件事现在同向**：统计缓存与边车里的 NoData 声明都不被取用（后者由批次 D 的 N184 收掉，见下面"注意事项"里那一条—— 别把这两件事混成
"边车整体不参与"。

## 处理流程

1. 打开输入栅格并定位指定波段。
2. 调用波段统计流程，得到最小值、最大值、均值和标准差。
3. 读取栅格宽高、波段数据类型和 NoData 声明——声明只取影像自身的（同名 `.aux.xml` 边车不参与，见注意事项）。
4. 将这些信息整理成文本摘要和元数据返回，不生成输出文件。

## 返回内容

- 最小值、最大值、均值、标准差
- 波段类型
- 栅格宽高
- NoData 值（若存在）

## 返回字段说明

- `min`：最小值
- `max`：最大值
- `mean`：均值
- `stddev`：标准差
- `width`：栅格宽度
- `height`：栅格高度
- `type`：波段数据类型，如 `Byte (uint8)`、`Float32`
- `nodata`：NoData 值，**只在波段声明过 NoData 时才出现这个键**；没声明时该键是"不存在"，不是存在但值为空。
  文本摘要里的 `NoData:` 那一行同理 —— 只在波段声明过 NoData 时才多出这一行。
  注意"声明了 NoData"不等于"像元里真的有 NoData 值"：声明值只要没出现在档值里，四个统计量与不声明时一致。
  "声明"只有影像自身这一条来源：只写进同名 `.aux.xml` 边车的 `<NoDataValue>` 不会被读回（见注意事项里的 N184）。

## 输出说明

- 本功能不生成输出文件。
- 统计结果直接显示在执行结果中，并附带对应元数据字段。

## 结果解释

- 结果适合快速判断波段值域、数据类型和是否存在异常分布。
- 如果存在 NoData，返回结果会显式带出 NoData 值。

## 适用场景

- 数据检查、阈值选择和处理前快速质检。

## 注意事项

- 当前只统计一个波段，默认统计第 `1` 波段。`band` 超出实际波段数时不返回半成品统计，而是整次失败
  （文案形如 `Cannot get band 9`，那个带号是按请求拼进去的）。
- **同名 `.aux.xml` 边车不参与读取**（批次 D 的 N184 起）：`core::openRaster` 给句柄置 PAM 的 `GPF_DISABLED`，
  影像自身的声明（GTiff 的 `GDAL_NODATA` 标签等）照旧读得到，而**只**写进边车的 `<NoDataValue>` 不再被读回
  （注入边车实测：改前打 `NoData: -9999` 并填 metadata `nodata: -9999.000000`，改后那一行整条不出现）。
  ⇒ 用本动作判"这张图有没有 NoData"看的就是影像自身声明，不必先清理边车；写出型动作也不会再把边车声明带进产物。
  副作用一并登记：句柄存活期间 PAM 的读写都关，所以这些动作**也不再产出** `.aux.xml`
  （实测一次 gaussian 滤波在输入与输出两侧都不落边车），缓存统计同样不被取用——与上一条"四个统计量每次重读像元"同向。
- 声明值不落在档值里时，四个统计量与不声明时一致（实测）；**声明值真的出现在档值里时会不会被排除在外，本动作没有
  承诺、也没有判据钉着** ⇒ 别把它当"自动屏蔽 NoData 像元"的统计工具用。
- 本功能没有输出文件参数，结果只在执行结果面板中显示；`type` 字段印的是带口径的类型名
  （8 位无符号给 `Byte (uint8)`，其余常见类型给同名串）。
- ⚠ 命令行仍要求写 `--output=`（见上文"输入与输出"那条 N183），那是一个不会被使用的必填项，
  不影响读数、也不会产出文件；在文档与脚本里给它填一个占位路径即可，别把它当成"统计会写到那儿"。
