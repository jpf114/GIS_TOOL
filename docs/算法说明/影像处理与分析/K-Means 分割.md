# 影像处理与分析 / K-Means 分割

## 功能说明

按所有波段特征对整幅影像做 K-Means 聚类分割。

## 输入与输出

- 输入：多波段或单波段栅格
- 输出：聚类标签栅格，建议 `.tif`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入影像。 |
| 输出文件 | 文件路径 | 是 | 无 | 输出聚类结果。 |
| KMeans K | 整数 | 否 | `4` | 聚类类别数，取值区间 `[2, 256]`。 |
| KMeans尝试次数 | 整数 | 否 | `3` | K-Means 的重复聚类次数（OpenCV `attempts`），必须大于 0。 |
| 最大迭代次数 | 整数 | 否 | `100` | K-Means 最大迭代次数。 |
| 收敛阈值 | 浮点数 | 否 | `0.001` | K-Means 终止阈值。 |

本动作没有"波段号"参数：聚类总是使用输入栅格的**全部**波段。`band` 是插件级声明的键，CLI 接受但对本动作无效（面板不显示，动作也不按它选波段）。

## 算法内容

K-Means 分割通过把每个像元看成一个多维特征点，在特征空间中自动聚成 `k` 类。当前实现不是只用单个波段，而是把输入栅格的全部波段一起作为特征参与聚类，因此输出结果更像“多波段无监督聚类标签图”。

## 处理流程

1. 打开输入栅格并读取全部波段。
2. 将每个像元在所有波段上的值拼成一个特征向量。
3. 把整幅影像展开成“像元数 × 波段数”的样本矩阵。
4. 按 `k`、最大迭代次数和收敛阈值运行 OpenCV K-Means（连同 `kmeans_attempts` 重复若干次，取紧致度最小的那一次结果）。
5. 得到每个像元所属的聚类标签和聚类紧致度。
6. 将聚类标签重新还原成原始影像尺寸，输出为单波段标签栅格。

## 输出说明

- 输出结果是单波段标签栅格（Float32 存储、取值为整数），建议使用 `.tif`。
- 像元值表示聚类标签，取值是 `0` 到 `聚类数-1` 的整数。
- 这些标签只代表“分到同一类”，不直接代表具体地物名称。
- 另一个可对照的量是**紧致度**（compactness）：每个像元到所属类心的距离平方和。它同时出现在结果的 metadata 与运行完成的提示文案里，两处是同一个数。

## 结果解释

- 标签值相同表示这些像元在当前多波段特征空间中被分到了同一类。
- 标签编号本身没有固定语义，不同次运行或不同数据之间不能直接按编号对照地物类别。
- OpenCV 的 K-Means 初值带随机成分 ⇒ 本动作不把“两次运行逐格相同”当契约：比对两次结果要看**分区结构**（哪些像元被分成同一类），不要比标签编号。

## 适用场景

- 无监督预分割、样本探索和多波段影像粗分类。

## 推荐输出文件名

- `kmeans_result.tif`
- `聚类分割结果.tif`

## 注意事项

- `聚类数`（`kmeans_k`）在实现层只拒**不大于 0** 的取值 ⇒ `k = 1` 不会被拒，与参数表声明的区间 `[2, 256]` 不一致（已登记，是否收紧待裁定）。
- `kmeans_attempts` 必须大于 0；`input` / `output` 缺失各自单独报错。这四条前置检查都在写产物之前 ⇒ 失败时不留下输出文件。
- 输入打不开（路径不存在等）时，底层 `openRaster` **直接抛异常**，本动作不会返回自己那句失败文案 ⇒ 那句 `Cannot open raster file: …` 实到读不到。
- 当前实现不会只取单波段，而是读取全部波段参与聚类；`k` 大于不同特征向量的个数时，重复向量会被拆进不同的簇（紧致度仍可以是 0）。
