# 影像处理与分析 / 分水岭分割

## 功能说明

执行分水岭分割，支持外部标记文件，也支持自动生成标记。

## 输入与输出

- 输入：
  - 输入影像
  - 可选标记文件
- 输出：分割标签栅格，建议 `.tif`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入影像。 |
| 输出文件 | 文件路径 | 是 | 无 | 输出分割结果。 |
| 波段号 | 整数 | 否 | `1` | 从 1 开始。 |
| 标记输入 | 文件路径 | 否 | 无 | 外部分割标记；留空则自动生成。 |

## 算法内容

分水岭分割把灰度影像看成地形表面，通过标记种子区域从低处向外扩展，最后在分界处形成边界。当前实现既支持外部提供标记图，也支持根据阈值、距离变换和连通组件自动生成标记。

## 处理流程

1. 读取输入影像指定波段，并转换为 8 位灰度图 —— 这一步不是类型转换：波段总是先读成 32 位浮点，再取**全幅 min/max** 做 `NORM_MINMAX` 线性拉伸并量化到 0..255（全幅为常数时整幅写 0）。⇒ "地形表面"的高度由该幅自身极值决定，且只有 256 级：小于 `(max-min)/256` 的微起伏被量化抹平，分水岭线随之改变。
2. 如果提供了 `标记输入`，则直接读取标记图并转为整型标记矩阵；标记值按"标记输入要求"一节所述约定原样送入分割，程序不会替用户做数值偏移。
3. 如果没有提供标记图，则先对灰度图做 Otsu 二值化。
4. 对二值结果进行膨胀，得到较稳的背景区域。
5. 对前景做距离变换，并按最大距离的一半阈值提取较稳的前景区域。
6. 对前景执行连通组件标记，再整体加 1：确定背景因此成为标签 `1`，各块前景种子从 `2` 起编号（OpenCV 的 `cv::watershed` 要求背景独占 `1`）。
7. 把种子编号偏移完成后，再将前景与背景之间的未知区域改写为 `0`（顺序不能颠倒，否则未知区会被一起抬成背景）。
8. 把灰度图转为三通道图像并执行分水岭分割。
9. 将分割结果转换为标签栅格：分水岭线写为 `-1`，其余正标签值原样写出——**确定背景的那个 `1` 也照样写进输出**，程序不做偏移或减 1。

## 输出内容

- 元数据返回 `segment_count`。

## 标记输入要求

如果提供 `标记输入`，应满足：

- 是一幅栅格文件
- 只比较**像元行列数**（不一致才失败）：程序**不比对**地理变换、投影或包络，也只用标记栅格的**第 1 波段** ⇒ 同尺寸但不同空间范围的标记图会被静默接受，产出一张整体错位的标签栅格；"对应到同一空间范围"要由用户自己保证。输出的地理参考取自**输入影像**而不是标记图。
- 其像元值可被转换为整型标记图

常见约定（与 OpenCV `cv::watershed` 的标记约定一致）：

- `1`：确定背景（必须是背景独占的一个标签）
- `2, 3, 4...`：不同的种子区域编号，从 2 起；允许不连续
- `0`：未知区域，留给分割算法填充；`-1` 在输入里没有意义

简单示意：

```text
1 1 1 1 1
1 2 2 0 3
1 2 2 0 3
1 1 1 1 3
```

上面表示存在两个种子区域，编号分别为 `2` 和 `3`；`1` 是确定背景，中间一列 `0` 是待算法填充的未知区。
若按 `0`＝背景、区域从 `1` 起编的老写法准备标记图，会有两处后果：
`0` 被算法当成未知区整片淹没；而编号 `1` 的那个区域被当成确定背景，不计入 `segment_count`
（同一幅标记，`segment_count` 会从区域总数少算 1，例如两区域报 `1` 而不是 `2`）。

注意：外部标记分支不做任何"约定转换"。用户标记里的 `0` 从像元值上无法区分是"背景"还是"未知"，
自动补偏移会把两类像元混为一谈，因此程序按字面读取——请按上面的约定准备标记。

如果不提供，代码会自动根据阈值、距离变换和连通域生成标记。

## 输出说明

- 输出结果通常是单波段标签栅格，建议 `.tif`。
- **输出的标签口径**：`cv::watershed` 跑完后，分水岭线被写成 `-1`，而**确定背景仍然保留它的标签 `1`**
  （输入约定里的 `1` 会原样出现在输出里）。⇒ 输出里**真正的分割区域从 `2` 起编号**；
  按"输出里 `1` 是第一个区域"去解读结果会**错一格**（那个 `1` 是背景，不是区域）。
  这里不做任何约定转换、也不给输出减 1：偏移会把背景与未知区重新混起来，正是本节上面裁定要避免的缺陷。
- 元数据中的 `segment_count` 表示分割出的区域个数：按 OpenCV 约定，确定背景 `1` 与分水岭边界 `-1` 都不计入，
  统计的是输出里 `>= 2` 的那些不同区域标签个数（不是最大标签值，所以外部标记编号不连续时也不会把标签空洞算进区域数）。

## 结果解释

- 输出不是分类图，而是分割标签图。
- 相同标签表示属于同一个分割区域，`-1` 表示分水岭边界。

## 适用场景

- 目标分割、区域生长前处理和标记分区任务。

## 推荐输出文件名

- `分水岭分割_result.tif`

## 注意事项

- 建议先确认输入波段号、数据类型和 NoData 设置是否正确 —— 更准确地说：**本动作不建 NoData 掩膜**，声明的哨兵值（如 `-9999`）会进入 min/max 拉伸（通常成为最低洼处）、Otsu、距离变换与 `cv::watershed`，最后以普通标签出现在输出里；哨兵被当成一个区域时 `segment_count` 也随之偏大。
- 输出结果受输入影像质量和参数设置影响较大。
