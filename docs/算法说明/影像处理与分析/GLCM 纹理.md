# 影像处理与分析 / GLCM 纹理

## 功能说明

按局部窗口计算灰度共生矩阵纹理特征，当前支持 `contrast`、`homogeneity`、`energy`、`entropy`。

## 输入与输出

- 输入：单波段或多波段栅格
- 输出：单波段浮点栅格，建议 `.tif`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入影像 |
| 输出文件 | 文件路径 | 是 | 无 | 输出纹理结果 |
| 波段号 | 整数 | 否 | `1` | 参与处理的波段 |
| 核大小 | 整数 | 否 | `5` | 纹理窗口大小，必须为不小于 3 的奇数 |
| GLCM指标 | 枚举 | 否 | `contrast` | 输出纹理指标 |
| GLCM灰度级 | 整数 | 否 | `8` | 量化灰度级数，必须不小于 2 |

## 算法内容

GLCM 纹理用于描述局部邻域内灰度组合关系。它不是直接看单个像元值，而是统计一个窗口内“某种灰度与另一种灰度相邻出现”的频率，再由这个灰度共生矩阵推导出纹理特征。当前实现支持 `contrast`、`homogeneity`、`energy`、`entropy` 四种常见纹理指标。

这类结果更适合表达局部纹理结构，而不是原始亮度。输出值高低的含义会随所选纹理指标变化，因此使用时需要先明确当前要突出的是“差异感”“均匀性”“能量集中度”还是“复杂度”。

## 处理流程

1. 读取指定波段，并转换为 8 位灰度数据。
2. 根据 `glcm_levels` 将原始灰度量化到较少的灰度级，降低共生矩阵规模。
3. 以 `kernel_size` 定义局部滑动窗口，在窗口内部**按四个方向各统计一张**灰度共现矩阵——方向偏移依次是
   `(dx,dy) = (1,0)、(1,1)、(0,1)、(-1,1)`（水平、主对角、竖直、副对角），**不是只看水平方向**。
   每个方向各自把自己那张矩阵的共现次数除以**该方向实际取到的对数**，算出一个纹理值。
4. 将共现次数归一化为概率分布，形成当前窗口的灰度共生矩阵。
5. 根据 `glcm_metric` 计算当前窗口的纹理值：
   - `contrast` 强调灰度差异
   - `homogeneity` 强调灰度接近程度
   - `energy` 强调概率集中程度
   - `entropy` 强调纹理复杂度
6. 把上面四个方向得到的纹理值**求和后除以 4**（四方向平均）写入该窗口的中心位置。
   ⚠ 统计某一对时只跳过**越出影像边界**的伙伴，不要求伙伴留在窗口内 ⇒ 窗口边缘那几列的
   取数范围会比窗口宽一格，四个方向的样本对数因此可以互不相同（各方向各自归一，不影响结论）。
7. 对整幅结果做一次 min-max 归一化，输出到 `0` 到 `1` 范围内的单波段浮点栅格。
   ⚠ 主循环只覆盖 `[radius, n-radius)` 那圈**内部**区域（`radius = kernel_size / 2`），最外一圈从未被写过、
   保持 0；而归一化取的 min/max 是**含这圈 0 的整幅**。四种指标的原始值都 >= 0 ⇒ min 必然就是那圈 0，
   所以产物里"边框 = 0.0"与"某窗口指标真的等于 0"**长得一样、来源不同**。
   又因为这一步是全局线性拉伸，**产物里读不到指标原值**（例如 `energy` 的 0..1 语义在产物里已被重标定）。

## 输出说明

- 输出结果会归一化到 `0` 到 `1`
- 不同 `glcm_metric` 对应不同纹理含义

## 结果解释

- `contrast` 值高，通常表示邻域灰度变化更明显，纹理更粗或边界更强。
- `homogeneity` 值高，通常表示邻域灰度更一致，区域更平滑。
- `energy` 值高，通常表示某些灰度组合更集中，纹理模式更稳定。
- `entropy` 值高，通常表示局部纹理更复杂、杂乱程度更高。
- 由于窗口边界处无法完整构造邻域，最外 `kernel_size / 2` 那一圈**不参与计算**，其输出值固定为 `0.0`——它**不是** NoData、也不是"纹理为 0"，与真实取到 0 的内部窗口在产物里无法区分。
  需要区分时请自行按窗口半径裁掉这一圈。

## 适用场景

- 纹理分区、目标识别前的特征提取。
- 区分平滑区、粗糙区、规则纹理区和复杂纹理区。
- 作为后续分类、分割或变化分析的辅助特征层。

## 推荐输出文件名

- `glcm_texture_result.tif`

## 注意事项

- `kernel_size` 必须为奇数
- `glcm_levels` 不能小于 2
- 窗口比影像还大时（`kernel_size / 2 >= min(行数, 列数)`）一个有效窗口都构造不出来，此时整幅原始值都是 0，归一化退化为"全写 0"⇒ **输出整幅 0.0 且不报错、返回码仍为成功**。这不是"纹理均匀"，是"根本没算过"；请核对窗口与影像尺寸的关系。
- `glcm_metric` 传入不支持的取值会被拒绝并返回 `Unknown glcm metric: <取值>`；但该判定发生在**逐窗计算的分支内部**，所以只有当影像确实存在至少一个有效窗口时才会触发——上一条那种"空内部"情形下会**静默成功**。是否应把指标合法性提前到参数校验阶段，属可观测行为变更，未在实现中调整。
