# 影像处理与分析 / 影像增强

## 功能说明

执行均衡化、CLAHE、归一化、对数增强、Gamma 校正等增强处理。

## 输入与输出

- 输入：栅格影像
- 输出：增强结果栅格，建议 `.tif`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入影像。 |
| 输出文件 | 文件路径 | 是 | 无 | 输出结果。 |
| 波段号 | 整数 | 否 | `1` | 从 1 开始。 |
| 增强类型 | 枚举 | 否 | `equalize` | `equalize` `clahe` `normalize` `log` `gamma`。 |
| 裁剪限制 | 浮点数 | 否 | `2.0` | `clahe` 时使用。 |
| Gamma | 浮点数 | 否 | `1.0` | `gamma` 时使用。 |

## 算法内容

影像增强用于改善单波段影像的对比度、亮度分布或细节可见性。当前实现支持全局均衡化、CLAHE、归一化、对数增强和 Gamma 校正几种常见方式，不同方法侧重不同。

## 处理流程

1. 读取输入影像指定波段。
2. 根据所选增强类型进入不同处理分支。**五个分支的前置处理并不相同**，逐支如下（不要合并理解）：
3. `equalize`：先按最小-最大值把数据拉伸并**量化成 8 位（256 级）**，再做全局直方图均衡，最后除以 255
   回到 `0-1`。映射表按上游 OpenCV 的累积分布口径生成：第一个占用档固定输出 0，其余档输出
   `round((cdf − cdf_min) × 255 ÷ (总像元数 − cdf_min))`。
   **档数一般保持不变，但不保证**：当某个较高占用档的乘积四舍五入后落到 `0`（或与相邻档同值）时，
   两档会被并成一档 ⇒ 输出档数**少于**输入档数。可复算的反例：总像元 `1024`、三档占用计数 `1 / 1 / 1022`
   ⇒ `scale = 255 ÷ 1023 ≈ 0.24927`，第二个占用档 `round(1 × 0.24927) = 0`，与"第一个占用档固定输出 0"
   并档 ⇒ 三档进、**两档出**。（这条是算术复算，不是产品实测。）
4. `clahe`：同样先**量化成 8 位**，再按 `8 × 8` 的**格子数**（不是 8×8 像素的格子尺寸）做对比度受限的局部均衡。
   图像尺寸不能被格子数整除时上游会先补边；相邻格子的结果之间还做双线性插值，
   所以**输出的档数会多于输入的档数**。整数裁剪上限按 `int(clip_limit × 格子面积 ÷ 256)` 再取 `max(…, 1)` 折算，
   因此它**不随 `clip_limit` 线性**，`clip_limit` 之间只要落在同一个整数上限上，产物就相同。
5. `normalize`：**不经过 8 位量化**，直接按原始浮点的最小-最大值拉伸到 `0-1`。
6. `log`：**不经过 8 位量化**；先把负值**截断为 0**（`cv::max(mat, 0.0, …)`，**不是平移**，负值信息在这一步丢失），
   再加 `1.0` 取对数，最后按对数结果的最小-最大值归一化。
7. `gamma`：**不经过 8 位量化**；先按原始浮点归一化，再取 **`1/gamma`** 次幂。
8. 将结果输出为单波段浮点栅格。

## 枚举值说明

### 增强类型

- `equalize`：直方图均衡化
- `clahe`：局部对比度受限均衡化
- `normalize`：归一化
- `log`：对数增强
- `gamma`：Gamma 校正

## 输出说明

- 输出结果为栅格文件。
- 建议优先使用 `.tif` 保存，便于后续在 CLI、GUI 或 GIS 软件中继续处理。

## 结果解释

- 不同增强方式的输出值可用于后续处理，但更主要是改善可视化和局部对比度。
- **`gamma` 的方向**：实现的指数是 `1/gamma`，所以 **`gamma` 大于 1 是提亮、小于 1 是压暗**。
  以归一后的中间调 `0.188679` 为例：`gamma=2` 得 `0.434372`（变亮），`gamma=0.5` 得 `0.035600`（变暗）。
  本节原先写的是"小于 1 提亮暗部、大于 1 压暗亮部"，与实现相反，批次 D P2a 按实现更正。
- **值域与精度逐支不同**（批次 D P2a 核对；不要当成一句共同的话）：
  - `equalize`：经 8 位量化 ⇒ 暗部细节上限就是 256 级；最高档输出**恰好** `1.0`，最低占用档输出**恰好** `0.0`。
  - `clahe`：输入同样量化到 256 级，但因格子间插值，输出值不止输入的档数；它的 `0-1` 边界
    **不保证**落在输入的极值档上。
  - `normalize`：**原始浮点**，保留输入的全部差异，不引入量化台阶。⚠ 它的最小档不是"严格等于 0"：
    当输入的最小值不为 0 时，实测该档落在 `0` 附近的 float32 舍入残差上（约 `-7e-9`），
    下游若要判"恰好 0"请改用 `equalize` 或在比较前给容差。
  - `log`：**原始浮点**；只有在输入非常量时才落在 `0-1`，常量输入时不归一化（见下一条）。
  - `gamma`：**原始浮点**（非常量支）；`0` 与 `1` 两个端点不随 `gamma` 移动。
- **常量输入（最小值等于最大值）时两支走法相反**（批次 D P2a 已各配一条单测判据钉住这个既有行为）：
  `gamma` 输出**全 0**；`log` **跳过归一化**、输出 `ln(x+1)` 的原值（例如整幅 200 时约 `5.3033`，**不在 `0-1` 内**）。
- **`clip_limit` 有区间闸，问题出在闸的下界本身就是那个退化值**：区间 `[0.0, 100.0]` 由框架侧的
  通用参数校验执行（`param_spec.h`），**越界会直接失败且不产出**——实测 `--clip_limit=-1.0` 与 `=1000.0`
  都是 `rc=1`、报「参数“CLAHE裁剪限制”超出范围 [0, 100]」、无产物。真正的问题是**下界 `0.0` 被放行到上游**：
  `clip_limit = 0` 使"受限"整段被跳过（局部均衡退化为不分格的均衡），产物与 `2.0` 明显不同
  （实测 `0.0` 给 Min `0.501961` / Mean `0.980842`，而 `2.0` 给 Min `0.105882` / Mean `0.415384`）；
  而 `0.001`、`1.0`、`2.0` 与不传该参数四者的 Min/Max/Mean/StdDev **四项统计量逐字相同**
  （本仓判据到统计量级，不比字节）⇒ 它们折在同一个整数裁剪上限上。
  ⇒ 该立案的是**下界取值**而不是"缺前置校验"，已记 **N181**，本版未修；需要受限对比度时请传 `1.0` 以上的值。
- 拼写错误的增强类型是**失败**（返回 `Unknown enhance type: <原值>`），不会回落到默认的 `equalize`。

## 适用场景

- 单波段显示优化、细节增强和后续分割前预处理。

## 推荐输出文件名

- `影像增强_result.tif`

## 注意事项

- 建议先确认输入波段号、数据类型和 NoData 设置是否正确。
- 输出结果受输入影像质量和参数设置影响较大。
