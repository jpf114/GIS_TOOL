# 栅格工具 / 金字塔

## 功能说明

为输入栅格构建多级金字塔，提高浏览和缩放性能。

## 输入与输出

- 输入：栅格文件
- 输出：原地修改输入文件，不生成新文件

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入栅格。 |
| 金字塔层级 | 字符串 | 否 | `2 4 8 16` | 多个级别用空格分隔。 |
| 重采样方式 | 枚举 | 否 | `nearest` | `nearest` `gaussian` `cubic` `average` `mode`。 |

## 算法内容

金字塔用于为栅格构建多级概览层，提高缩放浏览和快速显示性能。当前实现会把输入的层级字符串解析成一组有效缩放级别，然后调用 GDAL 的概览构建流程原地写回到原始栅格文件中。

## 处理流程

1. 以可写方式打开输入栅格。
2. 解析 `levels` 字符串，提取所有大于 1 的有效层级。
3. 如果没有有效层级，则直接报错。
4. 将重采样方式转换为 GDAL 所需的大写形式。
5. 调用 `BuildOverviews` 在原始栅格上构建概览层。
6. 原地保存结果，不生成新文件。

## 输出说明

- 本功能原地修改输入文件，不生成新的输出文件。
- 构建完成后可直接再次读取原文件查看概览层数是否增加。

## 结果解释

- 处理完成后，栅格文件会新增若干低分辨率概览层。
- 它不会改变原始全分辨率数据，只是增加用于快速浏览的附加层。

## 适用场景

- 大栅格浏览优化、发布前整理和桌面/服务端显示加速。

## 注意事项

- 只有大于 1 的层级会被实际采用。

## 枚举值说明

### 重采样方式

- `nearest`：最近邻
- `gaussian`：高斯
- `cubic`：三次卷积
- `average`：均值
- `mode`：众数

## 数值口径（批次 D R2 补，按实到）

- **本功能没有输出文件参数**：概览层由 GDAL 原地写进输入文件（内部 SubIFD 链），
  处理元数据 `GIS_PROCESSING` 域也写进同一个文件内部，不产生边车新文件。
- **底图不变**：全分辨率像元的取值、波段数、数据类型、宽高都不因建金字塔而改变；
  判据口径是"底图 `40 x 24 x 1 / Float32` 与统计量逐字保持原样"。
- **概览条数由 `levels` 串里 `>1` 的 token 决定，但不等于它的个数**：
  解析阶段只保留大于 1 的层级（`2 1 4 0 8` 这一串活下来的是 2、4、8 三个），
  而 GDAL 实际建出的条数**可以多于请求数**——实测在 40×24 的栅格上，
  请求 `{2,4,8}` 得 3 条，请求 `{4,8,16}` 得 4 条，请求 `{3,5,9}` 也得 4 条，
  多出来的是**更粗**的一级（最细那条仍对应请求里的最小因子）。
  因此"要几条概览"这件事只在层级本身构成从 2 开始的整倍链时才与请求数一致。
- **每级尺寸** = 底图宽 / 该级、底图高 / 该级，向上取整。实测 `40 x 24` 在层级 2、4、8 下
  依次是 `20 x 12`、`10 x 6`、`5 x 3`。
- **层级串全部无效时不产出**：只剩不大于 1 的层级（或空串）时直接报错退出，不会写出一个"没有概览的文件"。
- **重采样方式不参与上述任何一条判据**：`resample` 只影响概览像元的取值算法，
  条数与每级宽高都不随它变，所以它需要回读概览像元才能验证，当前 `raster_inspect info` 只报条数。
