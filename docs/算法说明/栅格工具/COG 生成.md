# 栅格工具 / COG 生成

## 功能说明

将输入栅格转换为 Cloud Optimized GeoTIFF，便于云端分块读取与快速浏览。

## 输入与输出
- 输入：栅格影像
- 输出：COG 栅格，建议 `.tif`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入栅格影像 |
| 输出文件 | 文件路径 | 是 | 无 | 输出 COG 文件 |

## 算法内容

COG 生成用于把普通栅格转换为 Cloud Optimized GeoTIFF。当前实现基于 GDALTranslate，以 `COG` 作为输出格式，并固定启用 `LZW` 压缩和 `BIGTIFF=IF_SAFER` 选项，生成更适合范围读取和云端访问的 GeoTIFF。

补充四点现读事实（批次 D R3a 写在用例与臂日志里的读数，不是从 GDAL 文档抄来的默认值）：

- 上面这三个转换选项写死在产品代码里，`ParamSpec` 一个都没暴露 ⇒ 用户**调不了**输出格式、压缩方式、
  瓦片尺寸与 BigTIFF 门槛；想换压缩方式属于改代码，不是在命令行或界面上加参数。
- 本机实测产物瓦片块尺寸是 **512 x 512**（`GDALRasterBand::GetBlockSize`）。
- 在能构造的尺寸档上（40x24 / 64x40 / 130x66 / 300x200）实测**金字塔层数都是 0**：小图没有可退的
  层级，所以『生成的 COG 一定带概览』这句不成立；要看金字塔得先有比瓦片大一档的输入。
- 生成之后产品还会**第二次打开输入**写处理元数据（含处理时间），这一步会把 IFD 重写到位图末尾，
  GDAL 当场印 `The IFD has been rewritten at the end of the file, which breaks COG layout`。
  批次 D R3a 拿臂实测过因果：把那次元数据写去掉，同一夹具的这条警告计数从 1 变 0 ⇒ 布局失效
  就是这一步造成的，不是翻译（GDALTranslate）本身。
- 因此**比较两个产物只能比尺寸 / 块尺寸 / 金字塔层数 / 统计量，不能比 md5 或逐字节**：处理时间每次都变，
  而且上面那条布局改写的存在与否会直接改变字节布局。

## 处理流程

1. 打开输入栅格。
2. 组装 COG 输出参数，固定使用 `COG` 格式、`LZW` 压缩和按需 BigTIFF。
3. 调用 GDALTranslate 执行格式转换。
4. 生成新的 COG 输出文件，并在元数据中记录格式和压缩方式。

## 输出说明

- 输出结果为 GeoTIFF
- 适合后续用于 Web 分发、云存储或高效浏览

## 结果解释

- 输出文件仍然是 GeoTIFF，但内部组织方式更适合分块读取。
- 转换重点是优化访问结构，不会主动修复源数据中的质量问题。

## 适用场景

- 云端发布、Web 浏览和大影像高效读取准备。

## 推荐输出文件名
- `output_cog.tif`

## 注意事项

- 输出文件通常比原始普通 TIFF 更适合范围读取
- 如果输入文件本身质量较差，转换不会自动修复数据问题
