# 栅格工具 / 直方图

## 功能说明

统计指定波段的直方图，可直接在结果中查看，也可导出为 JSON 文本文件。

## 输入与输出

- 输入：栅格文件
- 输出：
  - 可不写输出文件，仅在结果面板显示
  - 若导出文件，建议使用 `.json`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入栅格。 |
| 输出文件 | 文件路径 | 否 | 无 | 可选，导出直方图文本/JSON。 |
| 波段号 | 整数 | 否 | `1` | 从 1 开始。 |
| 柱数 | 整数 | 否 | `256` | 必须大于 `0`。 |

## 算法内容

直方图用于统计指定波段数值在整个值域中的分布情况。当前实现先计算波段统计范围，再按给定分箱数把值域划分为多个区间，最后统计每个区间的像元数量，并以文本加 JSON 结构形式返回。

两种边界情况的口径不同，不要混起来看：

- **最小值等于最大值**（整幅同一个值：常数栅格、只有一个像元的栅格、栅格化刚烧出来的产物）是**合法**的，本功能正常出结果。此时值域宽度为 `0`，无论 `bins` 填多少都只给 **1 个分箱**，该分箱的 `center` 就是那个唯一值、`count` 是有效像元数，文本头部会多一行 `Note: min == max …` 说明原因。
- **算不出统计**（整波段都是 `NoData`，或波段为空）才报错，案文是 `Band has no valid pixels to sample (every cell is NoData, or the band is empty)`。

改前这两类共用一句 `Band has no value range (min >= max)`：合法的常数栅格被判成"没有值域"，而真该报错的那张图给出的诊断还是假的（N133，2026-10-22 修）。

## 处理流程

1. 打开输入栅格并读取指定波段。
2. 统计该波段最小值和最大值。
3. 如果算不出统计（整波段都是 `NoData`，或波段为空），则直接报错并说明"没有有效像元"。
4. 按 `bins` 将值域划分为固定数量的分箱；若最小值等于最大值（常数栅格），只能给 1 个分箱。
5. 调用 GDAL 直方图统计流程，得到每个分箱的计数。
6. 计算分箱宽度和每个分箱中心值。
7. 生成文本头部和 JSON 风格的直方图结果。
8. 如果填写了输出文件，则把结果写入文件；否则只在结果面板返回。

## 输出内容

- 文本头部会写统计范围、分箱宽度。
- 后面附带 JSON 结构的直方图数组。

## 输出文件示例

```json
{
  "histogram": [
    {
      "bin": 0,
      "center": 0.5,
      "count": 123
    }
  ],
  "total": 123
}
```

## 输出说明

- 本功能可只返回文本结果，也可把结果写出到文件。
- 结果内容包含统计范围、分箱宽度和 JSON 结构的直方图数组。

## 结果解释

- 每个 `bin` 代表一个值域区间。
- `center` 是该区间中心值。
- `count` 是落入该区间的像元数量。

## 适用场景

- 栅格值分布检查、阈值选择和数据质量分析。

## 推荐输出文件名

```text
D:/data/scene_raster_histogram.json
```

## 注意事项

- 建议先确认输入栅格可正常读取，且输出格式与目标场景匹配。
- 批量运行前可先用单个样例验证参数设置。
- 常数波段（`min == max`）下元数据键 `bins` 回显的是**实际给出的分箱数 `1`**，不是用户填的 `bins`；`min`、`max` 两键仍然相等且都有效。
- `count` 与 `total` 统计的是**有效像元**（按掩膜跳过 `NoData`），不等于宽×高。
- 报"没有有效像元"和"值域宽度为 0"是两件事：前者失败、后者出值，两者案文不同（N133）。
- 分箱区间是左闭右开的 `[min + i·w, min + (i+1)·w)`，`w = (max - min) / bins`；**等于 `max` 的像元计入最后一个分箱**（实现按"超出范围也计入"的方式请求直方图，落在末档之外的值被归进首箱或末箱），所以各箱 `count` 之和等于有效像元数。JSON 尾部的 `total` 就是同一趟求和的结果，不是第二次统计 ⇒ 拿 `total` 与桶和对比判不出东西，要判就判**逐箱**的数。
- 三处印法各不相同，不能互相换算：文本头的 `Range:` 走缺省 6 位有效；`width=` 是定点 6 位；JSON 里的 `center` 是**定点 4 位**。桶心的小数位一旦超过 4 就会被舍入，而且落在正中线上时进位与舍去交替出现（桶宽 `15.9375` 的夹具实到 `7.9688`、`23.9062`、`39.8438`、`55.7812`）⇒ **不要拿 `center` 反推桶宽或下界**，要反推就用 `min`/`max`/`width=`。
- 元数据只有 4 枚键：`bins`、`min`、`max`、`total_pixels`。`min`/`max` 是定点 6 位小数的字符串（`std::to_string(double)`），`bins`/`total_pixels` 是整数串；除这 4 枚之外不发任何键 ⇒ 逐箱的中心与计数只能在文本/JSON 里取。
- `bins` 填得再大也不改变常数波段只有 1 个分箱这件事；反过来，非恒定波段**不会**按实际出现的离散值合并 —— 值只有 256 个也可能给出 65536 个空箱，箱宽由值域除以 `bins` 决定。
