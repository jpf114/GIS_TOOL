# 栅格工具 / 分区统计

## 功能说明

按矢量面要素对栅格进行分区统计，输出每个要素区域内的统计指标（最小值、最大值、均值、标准差、总和、像元数）。

## 输入与输出

- 输入：栅格 + 面矢量文件
- 输出：JSON 或 CSV 格式的统计结果

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入栅格 |
| 分区矢量 | 文件路径 | 是 | 无 | 面矢量分区文件 |
| 输出文件 | 文件路径 | 是 | 无 | 输出统计结果（`.json` 或 `.csv`） |
| 要素 ID 字段 | 字符串 | 否 | 空 | 矢量中标识每个分区的字段名，留空使用 FID |

## 算法内容

分区统计（Zonal Statistics）是栅格 GIS 中的核心分析功能。计算原理为：对矢量图层中的每个面要素，"
      "提取其空间覆盖范围内的所有栅格像元值，然后按波段逐区计算系列统计量。

统计**按输入栅格的全部波段**逐个进行，与 `band` 参数无关（本动作不读 `band`）：
一个要素有 k 个波段就产生 k 条统计记录。

`stddev` 用的是**总体标准差**：`variance = sumSq / count − mean²`，`variance > 0` 时取平方根，
否则记 0（单像元区间的 variance 恰为 0，因此 `stddev` 是 0，不是空值也不是 `nan`）。

此功能的计算方式与 ArcGIS Spatial Analyst 的 "Zonal Statistics as Table" 工具和 QGIS 的 "Zonal statistics" 工具一致，均基于矢量分区叠加栅格提取的逐像元方法。

输出的统计指标包括：

| 指标 | 说明 |
| --- | --- |
| min | 区域内最小值 |
| max | 区域内最大值 |
| mean | 区域内算术平均值 |
| stddev | 区域内**总体**标准差（除以像元数 n，不是 n−1） |
| sum | 区域内值总和 |
| count | 区域内有效像元数（排除 NoData） |

## 处理流程

1. 打开输入栅格，获取空间参考和地理变换参数；栅格缺地理变换时直接判失败。
2. 打开矢量文件，读取第一个图层。
3. 遍历每个面要素：
   a. 用要素的边界信封（Envelope）截取栅格子范围：列方向由信封的左右边算，行方向由信封的上下边算
      （行轴为负 ⇒ 上边给起始行、下边给结束行），两侧各钳一次到 `[0, 尺寸−1]`，除法结果向零取整。
      子范围的地理参考按起始列/起始行平移，掩膜因此与正确的像元子块对齐。
   b. 把要素烧成该子范围的掩膜，再对子范围内每个像元按**像元中心**是否落在要素内判定命中；
      未命中的像元不参与统计（即用掩膜而不是直接用包框）。
   c. 对命中的像元，先排除 NoData（与波段声明的 NoData 值之差小于 1e-9 即视为 NoData），再累计各统计量。
   d. 若截取结果左界大于右界（要素整个落在栅格范围之外），**该要素被静默跳过**：不报错、不告警，
      也不会出现在输出里。
4. 根据输出格式写入 JSON 或 CSV（由输出文件扩展名决定：`.csv` 走 CSV，其余走 JSON）。

### JSON 输出示例

```json
{
  "zone_A": [
    {
      "band": 1,
      "min": 100.5,
      "max": 850.3,
      "mean": 325.7,
      "stddev": 142.1,
      "sum": 65140.0,
      "count": 200
    }
  ]
}
```

### CSV 输出示例

```csv
feature_id,band,min,max,mean,stddev,sum,count
zone_A,1,100.5,850.3,325.7,142.1,65140.0,200
```

## 输出说明

- `.json`：结构化的嵌套 JSON，按要素 ID → 波段顺序组织。
- `.csv`：表头固定为 `feature_id,band,min,max,mean,stddev,sum,count`，每个 (要素, 波段) 一行，
  波段列是 1 起始的波段号。**行的先后顺序不保证**（结果先按要素 ID 汇总到哈希表里再写出），
  消费方应按 `feature_id` + `band` 选行，不要按物理行号取。
- 没有有效像元的分区不输出统计值：该行仍然写出（要素 ID 与波段号在），其余统计列留空。
  ⚠ 已知缺陷 N180：这样的空行比表头**少一列**（实现少写了一个逗号），所以不能假设 CSV 每行都是 8 列。
- 完全落在栅格范围外的要素连这一行都没有（见处理流程的静默跳过）。

## 结果解释

- `min`/`max` 越接近表示区域内像元值越均匀。
- `stddev` 越大表示区域内变异越大。
- `count = 0` 的分区在输出中不出现任何统计值。

## 适用场景

- 流域汇总（按子流域统计 DEM 的高程特征）。
- 行政区域汇总（按区划统计土地利用或 NDVI 特征）。
- 样方分析（按采样网格统计植被指数分布）。
- 栅格重分类后的面积统计。

## 推荐输出文件名

- `zonal_stats_result.json`
- `zonal_stats_result.csv`

## 注意事项

- 大数据量时逐像元包含测试计算量大，建议分区数量不超过 500 个。
- 栅格和矢量应使用相同的空间参考。本动作不做任何重投影：矢量与栅格坐标系不一致时，
  信封会被直接代进栅格的地理变换里算，结果可能整体偏移或落在栅格外。
- 跨越像元边界的要素按像元中心点判定归属。
- 可使用"要素 ID 字段"指定矢量中已存在的唯一标识列；留空时用要素的 FID。
  指定字段时**不同要素可能共用同一个 ID**（字段值相同即共用），此时它们的统计量会被累加进同一条记录。
- 结果里的 `zone_count` 是进了统计表的分区数，不是要素数：被静默跳过的要素不体现在任何输出面上，
  所以"跑成功"不等于"每个要素都算到了"。分区数与预期不符时先查栅格与矢量的范围是否相交。
