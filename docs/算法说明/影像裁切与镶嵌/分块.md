# 影像裁切与镶嵌 / 分块

## 功能说明

按固定像素块大小将输入栅格切分成多个小图块。

## 输入与输出

- 输入：单个栅格文件
- 输出：目录输出，内部自动生成多个 `.tif` 图块

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入栅格路径。 |
| 输出目录 | 文件路径 | 是 | 无 | 实际上这里应理解为输出目录路径。 |
| 分块大小 | 整数 | 否 | `1024` | 网格步长，单位像素；`overlap=0` 时它也就是每块的边长。 |
| 重叠像素 | 整数 | 否 | `0` | 相邻块之间的重叠像素数；只把每块加长，**不改块数也不改步长**。 |

## 算法内容

分块用于把一幅大栅格按固定像素窗口切成多个小图块。当前实现以固定块大小逐行逐列遍历整幅影像，并对每个块调用栅格窗口裁切流程输出单独文件。可选重叠像素用于让相邻图块之间保留边界冗余。

## 处理流程

1. 打开输入栅格，读取宽度、高度和波段数。
2. 检查输出目录是否存在，不存在则自动创建。
3. 按 `tile_size` 从左到右、从上到下遍历整幅影像。
4. 对每个块计算其左上角偏移、实际宽高以及可选重叠范围。
5. 按 `srcwin` 参数调用 GDALTranslate 截取当前窗口。
6. 按 `tile_x_y.tif` 规则生成图块文件名。
7. 循环直到整幅影像被分割完毕。

## 处理逻辑

- 如果输出目录不存在，代码会自动创建。
- 输出文件命名形如 `tile_x_y.tif`。
- 网格算术的**实到口径**（与"重叠像素"常见直觉不同，逐条写准）：
  - **步长恒为 `分块大小`**（`for (xOff = 0; xOff < width; xOff += tileSize)`），`重叠像素` **不进步长**；
  - 块数 = `ceil(宽 / tile_size) × ceil(高 / tile_size)` ⇒ **与 `overlap` 完全无关**；
  - 每块尺寸 = `min(tile_size + overlap, 该方向剩余)` ⇒ `overlap` 只把每块**加长**，不改网格；
  - 块名里的 `x`/`y` 是 `xOff / tile_size`、`yOff / tile_size`，即"第几个步长格"，与 `overlap` 无关。
- 手算例（夹具 30×20）：`tile_size=16, overlap=0` ⇒ `2×2=4` 块，首块 16×16、末块 `min(16,14)×min(16,4)=14×4`；
  `tile_size=16, overlap=4` ⇒ **仍是 4 块**，首块涨到 20×20、末块仍是 14×4；
  `tile_size=8, overlap=0` ⇒ `4×3=12` 块，末块 6×4；`tile_size=8, overlap=3` ⇒ **仍是 12 块**，首块涨到 11×11、末块仍 6×4。
- ⚠ **末块尺寸对 `overlap` 不敏感**：`min(·, 剩余)` 先把 `overlap` 吃掉（上面两例的末块在 ov=0/3 两档都是 6×4）
  ⇒ 末块不能用来证明"重叠被消费了"，能证明的只有首块与内部块的尺寸。
- 退化输入 `overlap ≥ tile_size` **不校验、不报错**（参数区间只限 `overlap ∈ [0, 65536]`）：
  实测 6×6 影像上 `tile_size=4` 配 `overlap=6` 与 `overlap=10` 得到**完全相同**的四块网格
  （6×6、2×6、6×2、2×2），因为尺寸早被包框夹住 ⇒ 这种档位区分不了实现有没有真的读 `overlap`，
  不要把它当判据用。

## 结果解释

- 输出不是单个文件，而是一组按行列编号命名的小图块。
- 设置重叠像素后，相邻图块边缘会包含重复区域，便于后续拼接或边缘处理。
  重复带的宽度就是 `overlap`：块 `k` 覆盖源列 `[k·tile_size, k·tile_size + tile_size + overlap)`，
  与块 `k+1` 的公共部分是 `overlap` 列（末块被影像边缘夹住时可能更少）。

## 适用场景

- 大影像切块处理、模型推理前分片和分布式任务准备。

## 输出说明

- 输出为目录，其中会自动生成多个 `.tif` 图块文件。
- 图块名称按 `tile_x_y.tif` 规则生成。

## 推荐输出文件名

- `tiles/`

## 注意事项

- GUI 当前参数名叫“输出文件”，但代码真实语义更接近“输出目录”。
- 判据凭据（Debug）：`PluginTest.CuttingSplitTileGridHandTableAcrossTileSizeAndOverlap` 是一张
  **两档 `tile_size` × 两档 `overlap` 的手算表**（30×20 夹具上 4 档：块数 4/4/12/12、首块 16×16 / 20×20 /
  8×8 / 11×11、末块 14×4 / 14×4 / 6×4 / 6×4），每档还读**块内像元值**——夹具值 = `(30·y + x) % 256`，
  于是"块 (tx,ty) 的局部 (0,0) 必须等于源 `(tx·tile_size, ty·tile_size)`"是可手算的期望，
  `overlap>0` 的两档另加一枚"首块右边缘与邻块左边缘读到**同一个**源像元"。
  取证三臂：`min(tileSize + overlap, 剩余)` 丢掉 `overlap` ⇒ 只有 `ov>0` 两档红（首块尺寸 + 重叠带读空）；
  把 `overlap` 折进步长 ⇒ 块数、首块尺寸与"末块根本没产出"三支红；`ov=0` 档与旧用例
  `CuttingSplitExecutionCreatesTiles` 保持绿（那里 `overlap` 本来就是 0，臂无从生效）。
- 腿侧（`real_data_raster`）：`cutting_split` 判 `ceil(6/4)²=4` 块与四块按**块名**取的宽高
  （4×4、2×4、4×2、2×2 —— `2×4 / 4×2` 这一对就是轴序载体），新 case `cutting_split_overlap`
  用 `tile_size=4, overlap=2` 判"块数仍是 4、首块涨到 6×6、邻块 2×6 / 6×2"。
  两处的形状都是把 `raster_inspect info` 的 `Size:` 行**解析成整数再逐支比较**，不是文本子串。
  ⚠ 限制照实登记：腿的夹具每格都是 `1`，`Mean` 只证明块里确实是源数据；`tile_1_1` 在 ov=0/2 两档逐维相同，
  所以它不是 `overlap` 的证据。
