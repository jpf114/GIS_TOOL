# 影像裁切与镶嵌 / 栅格切片

## 功能说明

将栅格数据按 XYZ/TMS 标准 Web 地图瓦片方案切片，输出 `z/x/y.png` 目录结构，可直接部署为地图瓦片服务。

## 输入与输出

- 输入：单波段或多波段栅格
- 输出：瓦片目录（`z/x/y.png`）+ `metadata.json`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入栅格 |
| 输出目录 | 目录路径 | 是 | 无 | 瓦片输出目录 |
| 瓦片编号方案 | 枚举 | 否 | `xyz` | `xyz`（y=0在北）或 `tms`（y=0在南） |
| 切片剖面 | 枚举 | 否 | `mercator` | `mercator`=EPSG:3857, `geodetic`=EPSG:4326, `raster`=不重投影 |
| 最小缩放层级 | 整数 | 否 | `0` | 瓦片金字塔的最小缩放层级 |
| 最大缩放层级 | 整数 | 否 | `-1`(自动) | -1 表示根据影像分辨率自动计算 |
| 瓦片像素尺寸 | 整数 | 否 | `256` | 每个瓦片的像素宽高（128/256/512/1024） |
| 重采样方法 | 枚举 | 否 | `average` | 降采样重采样算法 |
| 概览重采样 | 枚举 | 否 | `nearest` | 金字塔概览图的重采样方法 |
| 瓦片输出格式 | 枚举 | 否 | `png` | `png`/`jpeg`/`webp`/`gtiff` |
| JPEG压缩质量 | 整数 | 否 | `75` | JPEG/WebP 压缩质量（1-100） |
| 添加透明通道 | 布尔值 | 否 | `true` | 为瓦片添加 Alpha 透明通道，NoData 区域变透明 |

| 切片范围 | 范围 | 否 | 全图 | 自定义范围（xmin,ymin,xmax,ymax WGS84） |

| 版权信息 | 字符串 | 否 | 空 | Web 预览页面的版权信息 |
| 并行线程数 | 整数 | 否 | `1` | 瓦片生成的并行线程数 |

## 算法内容

栅格切片是将连续的栅格数据按 Web 地图标准瓦片网格分割为离散瓦片的过程。核心步骤包括：

1. **重投影**：将输入栅格重投影到目标坐标系（mercator→EPSG:3857, geodetic→EPSG:4326）。
2. **多级金字塔**：对每个缩放层级，先降采样到该层级对应的全局像素尺寸，再按瓦片网格切割。
3. **瓦片编号**：根据经纬度范围和 zoom level 计算起止瓦片行列号，支持 XYZ 和 TMS 两种编号方案。
4. **透明处理**：将 NoData 像素转为 Alpha=0（完全透明），支持 PNG/WebP 格式输出。
5. **空白跳过**：检测全透明瓦片并跳过，减少存储空间。

与 QGIS "Generate XYZ tiles"、ArcGIS "Manage Tile Cache" 和 GDAL `gdal2tiles` 的核心算法一致。

### 自动 max_zoom 计算

Web Mercator 各层级地面分辨率：

```
resolution(z) = 2π × 6378137 / (tileSize × 2^z)
```

自动计算：找到最大的 z 使得 `resolution(z) >= 输入栅格的地面分辨率 × 0.5`。

### XYZ 与 TMS 的区别

| 方案 | y=0 位置 | 转换公式 |
| --- | --- | --- |
| XYZ | 左上角（北极） | 直接使用计算值 |
| TMS | 左下角（南极） | `y_tms = 2^z - 1 - y_xyz` |

## 处理流程

1. 打开输入栅格，读取空间参考、地理范围、分辨率。
2. 根据 profile 确定目标坐标系，若需重投影则调用 GDALWarp。
3. 若 max_zoom = -1，根据影像分辨率自动计算。
4. 将影像边界转换为 WGS84 经纬度范围。
5. 逐 zoom level：
   a. 计算该层级全局像素尺寸。
   b. 对非最高层级，用 GDALTranslate 降采样。
   c. 计算覆盖的瓦片行列号范围。
   d. 逐瓦片提取、缩放到 tileSize×tileSize、NoData 转透明、编码输出。
6. 生成 metadata.json（TileJSON v3.0 格式）。
7. 若指定 webviewer，生成 Leaflet/OpenLayers 预览页面。

```
output_dir/
├── metadata.json

```

### metadata.json 格式

遵循 TileJSON v3.0 规范，包含瓦片方案的完整描述信息，可直接被 Leaflet、MapLibre、OpenLayers 等 Web 地图库加载。

## 结果解释

- 每个瓦片为 256×256（默认）像素的 PNG/JPEG/WebP/GeoTIFF 图像。
- NoData 区域为透明像素（Alpha=0）。
- 瓦片可直接部署到 Nginx/Apache 等 Web 服务器作为静态瓦片服务。

## 适用场景

- 将 DEM/卫星影像发布为 Web 地图底图。
- 生成离线地图瓦片包供移动端使用。
- 构建内部 GIS 瓦片服务。
- 大范围栅格数据的快速可视化预览。

## 推荐输出目录名

- `tiles_dem/`
- `tiles_satellite/`

## 注意事项

- 输入栅格应有正确的空间参考信息，否则重投影可能失败。
- 大范围高分辨率影像的 max_zoom 可能较高（如 18-22），瓦片数量会指数增长，建议设置合理的 max_zoom。
- mercator 剖面下纬度范围限制在 ±85.05°。
- 续切模式（resume）可中断后继续，仅生成缺失的瓦片。
- JPEG 格式不支持透明，若需透明背景请使用 PNG 或 WebP。
