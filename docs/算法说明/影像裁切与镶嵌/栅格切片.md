# 影像裁切与镶嵌 / 栅格切片

## 功能说明

将栅格数据按 XYZ/TMS 标准 Web 地图瓦片方案切片，输出 `z/x/y.png` 目录结构，可直接部署为地图瓦片服务。

## 输入与输出

- 输入：单波段或多波段栅格
- 输出：瓦片目录（`z/x/y.png`）+ `metadata.json`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |

## 算法内容

栅格切片是将连续的栅格数据按 Web 地图标准瓦片网格分割为离散瓦片的过程。核心步骤包括：

1. **重投影**：目标坐标系恒为 EPSG:3857。`profile` 目前**只实现 `mercator`**；`geodetic` 与 `raster` 会显式失败（`tile profile "…" is not supported yet; only profile=mercator is implemented`），不会退回经纬度网格或原坐标系（枚举取值与实现面的不一致已挂账 N48）。
2. **分级但不物化金字塔**：整幅只重投影一次成 EPSG:3857 的中间数据集；zoom level 只用来确定索引网格，**每个层级不再各自物化一张全球降采样图**（该做法在 R-T17-7 已删除），每瓦片按反算读窗直接从中间数据集取块再缩放。
3. **瓦片编号**：起止行列号由 **EPSG:3857 度量范围**推导（`floor((x - worldMinX) / tileWidth)`），不做“度量→经纬度→索引”的往返；用户给的瓦片范围反而要先前向投影到 3857 再参与计算。XYZ 与 TMS 只差 y 的编号方向。
4. **透明处理**：将 NoData 像素转为 Alpha=0（完全透明），支持 PNG/WebP 格式输出。
5. **空白跳过**：不是“全透明”才跳 —— 瓦片内**不透明像元 ≤ 4** 即判为空并跳过（`kBlankOpaquePixelTolerance = 4`）。

与 QGIS "Generate XYZ tiles"、ArcGIS "Manage Tile Cache" 和 GDAL `gdal2tiles` 的核心算法一致。

### 自动 max_zoom 计算

Web Mercator 各层级地面分辨率：

```
resolution(z) = 2π × 6378137 / (tileSize × 2^z)
```

自动计算：找到最大的 z 使得 `resolution(z) >= 输入栅格的地面分辨率 × 0.5`。两点前提正文必须交代：自动值与用户显式值最后都会被**硬钳到 22**（`maxZoom = min(maxZoom, 22)`）；而“输入栅格的地面分辨率”取的是**源 CRS 单位**下的像元大小，与上式的“米/像元”直接比较 ⇒ 源是地理坐标系（度）时这个自动值只有量级意义，应自行指定 max_zoom。

### XYZ 与 TMS 的区别

| 方案 | y=0 位置 | 转换公式 |
| --- | --- | --- |
| XYZ | 左上角（北极） | 直接使用计算值 |
| TMS | 左下角（南极） | `y_tms = 2^z - 1 - y_xyz` |

## 处理流程

1. 打开输入栅格，读取空间参考、地理范围、分辨率。
2. 校验空间参考与像元网格：**没有 CRS 直接失败**，且必须是 north-up 零旋转网格（x 像元大小 > 0、y < 0、旋转/斜切项为 0），否则失败。目标坐标系恒为 EPSG:3857。
3. 若 max_zoom = -1，根据影像分辨率自动计算。
4. 将影像边界转换为 WGS84 经纬度范围。
5. 逐 zoom level：
   a. 计算该层级覆盖的索引网格范围（不物化该层级的全球影像）。
   b. （曾经这里是“对非最高层级用 GDALTranslate 降采样到全局像素尺寸”，R-T17-7 已删除该物化步骤。）
   c. 计算覆盖的瓦片行列号范围。
   d. 逐瓦片在中间数据集上反算读窗取块，缩放到**瓦片内的目标子矩形**（内部瓦片子矩形恰为整张；边缘部分覆盖的瓦片按覆盖比例放置，未覆盖的边留在透明上），NoData 转透明、编码输出。
6. 生成 metadata.json（TileJSON v3.0 格式）。
7. 只有 `webviewer=leaflet` 或 `all` 会生成 Leaflet 预览页；**`openlayers` 没有实现分支**（选了既不产出也不报错），该取值同样属 N48 的“枚举宽于实现”。

## 输出说明

### 目录结构

```
output_dir/
├── metadata.json
├── leaflet.html              (可选)
├── 0/
│   └── 0/
│       └── 0.png
├── 1/
│   ├── 0/
│   │   ├── 0.png
│   │   └── 1.png
│   └── 1/
│       ├── 0.png
│       └── 1.png
└── ...
```

### metadata.json 格式

遵循 TileJSON v3.0 规范，包含瓦片方案的完整描述信息，可直接被 Leaflet、MapLibre、OpenLayers 等 Web 地图库加载。

## 结果解释

- 每个瓦片为 256×256（默认）像素的 PNG/JPEG/WebP/GeoTIFF 图像。
- NoData 区域为透明像素（Alpha=0）。
- 瓦片可直接部署到 Nginx/Apache 等 Web 服务器作为静态瓦片服务。

## 适用场景

- 将 DEM/卫星影像发布为 Web 地图底图。
- 生成离线地图瓦片包供移动端使用。
- 构建内部 GIS 瓦片服务。
- 大范围栅格数据的快速可视化预览。

## 推荐输出目录名

- `tiles_dem/`
- `tiles_satellite/`

## 注意事项

- 输入栅格必须有空间参考、且为 north-up 零旋转像元网格，否则本动作**必然失败**（不是“可能失败”）。
- 大范围高分辨率影像的 max_zoom 会很高（如 18-22），瓦片数量指数增长；**max_zoom 无论自动还是手动都被硬钳到 22**，超过 22 的需求要换工具。
- mercator 剖面下纬度范围限制在 ±85.05°。
- 续切模式（resume）可中断后继续，仅生成缺失的瓦片。
- JPEG 格式不支持透明，若需透明背景请使用 PNG 或 WebP。
