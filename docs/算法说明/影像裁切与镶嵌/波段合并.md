# 影像裁切与镶嵌 / 波段合并

## 功能说明

将多个单波段栅格按顺序合并成一个多波段栅格。

## 输入与输出

- 输入：多个单波段栅格
- 输出：多波段栅格，建议 `.tif`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 否 | 无 | 可传逗号分隔文件列表。 |
| 波段列表 | 字符串 | 否 | 无 | 额外文件列表，逗号分隔。 |
| 输出文件 | 文件路径 | 是 | 无 | 输出多波段栅格。 |

## 算法内容

波段合并用于把多个单波段栅格按给定顺序组合成一个多波段栅格。当前实现会先把所有输入文件组织成一组波段来源，再通过 VRT 的 `-separate` 模式把它们拼成虚拟多波段，再转换成实际输出文件。

## 处理流程

1. 读取 `输入文件` 和 `波段列表`。
2. 将两处输入统一拆分并拼接成最终波段文件列表。
3. 检查至少存在一个可用输入文件。
4. 逐个打开这些单波段栅格。
5. 以 `-separate` 方式构建一个多波段 VRT。
6. 将该 VRT 再转换为实际多波段输出栅格。
7. 按输入顺序保持输出波段顺序。

## 填写示例

### 方式一：全部写在 `输入文件`

```text
D:/data/b1.tif,D:/data/b2.tif,D:/data/b3.tif
```

### 方式二：`输入文件` + `波段列表`

输入文件：

```text
D:/data/b1.tif
```

波段列表：

```text
D:/data/b2.tif,D:/data/b3.tif
```

### 输出说明

- 输出结果为栅格文件。
- 建议优先使用 `.tif` 保存，便于后续在 CLI、GUI 或 GIS 软件中继续处理。

## 推荐输出文件名

```text
D:/data/merged_bands.tif
```

## 处理逻辑

- `输入文件` 和 `波段列表` 至少填一个。
- 两者会被拼接成统一输入列表，再按顺序合并：最终列表 = `输入文件` 逗号拆开的项 **接上** `波段列表` 逗号拆开的项。
- **`波段列表` 吃的是文件路径，不是波段索引**：实测 `--bands=1` 返回失败，案文 `Cannot open file: 1`。
  ⚠ 同一份 `gis-cli cutting --help` 把 `--bands` 的英文描述写成 "Comma-separated band indexes"，
  与实现不一致（登记为缺口，文档这里按实现写）。
- 输出波段数 = 列表长度 ×（各元素自己的波段数）：列表中每个文件贡献它**自己的全部波段**，
  按文件顺序、文件内波段顺序展开。三带文件 + 单带文件 ⇒ 4 带，不是 2 带。
- 输出第 k 带 = 拼接列表第 k 个来源波段 ⇒ 交换 `波段列表` 里的两项会让对应两带的**内容互换**。
- 列表里的**重复路径不去重**：同一个文件写两遍得到两带内容相同的波段（实测 rc=0）。
- 各输入的**地理参考不同**时，VRT 取的是包框的**地理并集**：产物会比任何一个输入都大，
  而每个来源在自己包框之外的部分补 0 ⇒ 统计量被稀释（实测两张 10×6 常量图 origin 差 10 列时，
  Mean 从 10.0 变成 5.0）。要让波段严格对齐，请先把它们重投影/裁到同一包框。
- 元数据（`writeProcessingMetadata`）取的是列表里**第一个**文件的口径。

## 结果解释

- 输出结果是一幅新的多波段栅格。
- 输出第 1、2、3... 波段顺序，直接对应输入文件列表顺序。

## 适用场景

- 单波段数据重新组装为多波段影像。
- 为后续指数计算、分类或渲染准备标准多波段输入。

## 注意事项

- 输出建议使用 `.tif`。
- 判据凭据（Debug）：`PluginTest.CuttingMergeBandsOrderShuffleAndRepeatedFile` 用**三个不同常量**的
  同尺寸同 origin 夹具（10 / 20 / 30）跑五档：`input`+`bands` 拼接 ⇒ 3 带逐带 10/20/30；
  `bands` 两项打乱 ⇒ 第 2、3 带内容**互换**（10/30/20）；`bands=B,B` 重复 ⇒ 3 带 10/20/20（不去重）；
  只给 `input` ⇒ 1 带（列表长度下界）；`input` 是三带常量图 + `bands` 一个文件 ⇒ 4 带 10/20/30/30
  （判"每文件整份展开"，只取每文件第 1 带的实现会在这里塌成 2 带）。逐带断言的是**像元值**，
  期望全部来自生成器的常量字面量；相邻两档差 10、容差 1e-4f ⇒ 两头都夹开。
  ⚠ 既有的 `CuttingMergeBandsCreatesMultiBandRaster` / `…CombinesInputAndBandsList` 用的是
  `createTestRaster` ⇒ 三个文件内容逐字节相同，在它们身上**判不出顺序**（这是本把另写用例的直接原因）。
  取证两臂：吞掉 `bands` 列表 ⇒ 逐带断言的 4 档红（`bands` 空的那档与腿侧 case 保持绿，因为它们本来就没用该键）；
  把拼接列表反序 ⇒ 红在逐带像元值上（第 1 带差 20 / 第 2 带差 10）。
- 腿侧（`real_data_raster`）：`cutting_merge_bands` 现在按**带号**取数再比容差
  （第 1/2/6/7/8/12 带 Mean = 10/20/110/10/20/110，期望来自 `makeNdviRaster` 的六个常量字面量；
  第 12 带 `StdDev = 0`），并判 `Size: 24 x 24 x 12` 的三个整数（12 = 6+6 列表长度手算）。
  ⚠ 限制照实登记：该 case 的两条列表项是**同一个文件** ⇒ 腿判不出"哪个文件在前"，
  列表反序臂下腿侧 rc=0（实测），文件顺序只有单测侧那一档判得到；给腿换一个不同常量的第二输入
  归后续批次。另外旧的 `Contains "Mean:   110"`（只证明文本里有这串字）已被按带取数取代。
