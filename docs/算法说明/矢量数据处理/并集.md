# 矢量数据处理 / 并集

## 功能说明

把输入图层与叠加图层做**真并集**：输出覆盖“输入 ∪ 叠加”的全部空间范围，并把两侧的字段合并到同一张输出表里，另带一个 `source` 标记说明每一块几何的来源。

例外：输入是线、叠加是面时（混合维度那一格）输出仍然是线图层，只有被切分的线段、不产出叠加面，两侧的字段照样合并进同一张表（详见“算法内容”）。

## 输入与输出

- 输入：
  - 输入矢量图层
  - 叠加矢量图层
- 输出：并集结果图层，建议使用 `.gpkg`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 主输入图层 |
| 输出文件 | 文件路径 | 是 | 无 | 并集结果输出路径 |
| 图层名 | 字符串 | 否 | 无 | 输入图层名 |
| 叠加矢量 | 文件路径 | 是 | 无 | 第二个参与并集的图层，默认取其第一个图层 |

## 算法内容

并集前，叠加图层几何会先做标准化处理，必要时尝试自动修复非法几何。按输入图层的几何维度分成两条路径：

- **普通路径**（输入不是线，或叠加不是面）：输出由三类**互不重叠**的分块拼成，三类面积相加正好等于并集面积。
  1. 相交块：输入几何与某条叠加几何的交集，写出前先减掉“这条输入要素已经写过的相交面积”；
  2. 输入独有块：输入几何减去“这条输入要素本轮已经写出的相交块”。它与“输入几何减去全部候选叠加几何的并”可证等价
     （相交块就是交集逐条减掉已写面积的结果），但减法基拿的是本工具已经算在手里的面积，
     不依赖再一次级联并集 —— 候选并集构造失败时也不会退化成“整块克隆写出”那种与相交块重叠的结果；
  3. 叠加独有块：叠加几何减去“全部输入几何的并”，再减去“之前已经写出的叠加面积”。
  叠加面之间互相重叠时，第 1 步和第 3 步的“减掉已写面积”是必需的 —— 不减就会把同一块面积写两次。
  每条叠加几何只按包串粗筛参与它相交的输入要素，不重新读图层。
  几何运算失败时本路径选择**宁缺不重**：减不动的分块跳过不写。但这句话只覆盖"整个差集运算返回失败"那一类，
  **不覆盖下面三类失败**，它们仍可能留下重叠或缺口，而且只有叠加独有块的整块跳过会计数：
  ① `已写面积` 累加时某一次并集返回失败 ⇒ 减法基少一块，源独有块会把已写出的相交面积再算进去（不计数）；
  ② 逐条差集只减动了一部分候选 ⇒ 写出的叠加独有块与没减动那条源几何重叠（不计数）；
  ③ 候选并集走的是级联并，子树失败时返回"只并了一半"的**非空**结果 ⇒ 少减一条且不计数。
  这三类今天都没有判据（要 GEOS 返回失败才可达），登记为挂账随取证刀处理。
  叠加独有块这类缺口记进 `union_skipped_overlay_pieces`（源独有块的缺口今天不单独计数，只体现为条数与面积偏少）。
- **线 × 面路径**（输入是线、叠加是面）：走更实用的混合维度逻辑，先按叠加面边界把线切成多个片段再写出。
  这一路的输出仍然是**线图层**：线与面在维度上不相容，把叠加面作为面要素写进线图层不是本动作的行为，
  所以它只保证**线段被完整切分覆盖**、**不产出叠加面** —— `union_overlay_pieces` 在这一路恒为 0，那是契约不是缺陷。
  属性表与普通路径**同一条规则**（源字段原序 → 叠加字段 → 标记列，见“输出说明”）：每条片段带着**它自己那条源线**的
  整表字段，落在某个叠加面里的片段再带着**那一条叠加面**的整表字段，面外片段的叠加侧字段全为 NULL。
  这一路的标记值只有 `both`（片段被某条叠加面盖住）与 `input`（片段在所有叠加面之外）两种。
  这一路的可加不变量是**长度可加**：写出的所有片段长度之和 == 源线要素长度之和（不重不漏）；
  普通路径那句“分块面积相加等于并集面积”在这一路不适用（这一路没有面要素可加）。
  片段取哪一条叠加面的属性是**唯一确定**的：在包串与片段相交的叠加要素里，按叠加图层读取顺序取第一个
  盖得住整条片段的那个。两条叠加面**互相重叠**时同一片段可能被两条同时命中，"取第一个命中"因此只是本工具的约定 ——
  它成立的前提是一道**只看外包矩形**的闸：叠加几何**不少于 3 条**、且两两包串相交的要素对占比 ≥ 0.25 时才拒绝执行（见“注意事项”）。叠加图层只有 1-2 条面时这道闸结构上不可能触发，此时片段归属就只是按读取顺序的约定。
  "片段贴在叠加面边界上"（差集结果保留切口端点）不算被这条面盖住，仍写 `input`。

## 处理流程

1. 打开输入图层和叠加图层。
2. 检查两者 CRS 是否一致，不一致直接失败。
3. 逐条标准化叠加图层几何：**某条几何自动修复失败时只丢掉那一条**（不报错、也不计入任何跳过计数），该块面积从并集里凭空缺失；只有叠加图层里一条几何都没能留下时才整条失败。
4. 若是“线 + 面”的混合维度，再判断“叠加几何 ≥3 条且包串相交对占比 ≥0.25”，命中则拒绝执行。
5. 创建输出图层并建表：两条路径共用同一条规则合并两侧字段并追加标记列（规则见“输出说明”）。
6. 逐条处理输入要素：普通路径先写相交块、再写输入独有块；线 × 面路径切分线段，逐条片段查归属叠加面并写出。
7. 普通路径继续逐条处理叠加要素，写出叠加独有块（不与任何输入要素相交的那部分）；线 × 面路径没有这一步
   （这一路不产出面要素，见“算法内容”）。
8. `.gpkg` 输出按事务批量写入，空间索引全程交给 GeoPackage 驱动：建图层时不关索引，写盘收尾由驱动一次性回填 rtree。
   ⚠ 早先这一条写的是“先 `SPATIAL_INDEX=NO` 批量写、收尾再 `gpkgAddSpatialIndex` 补建索引”，与实际行为不符：
   那个函数只建 rtree 表和触发器、**不回填已经在表里的行**，交出的产物是“扩展项已登记、rtree 0 行”，
   任何带包框的读端拿到的都是 0 个要素（N138，该写法已删除）。`clip`/`dissolve`/`union`/`difference`/`intersect`
   原来都走这一条，`buffer` 从一开始就没开事务批量化（`useTransactions = false`）、交出的索引一直是回填过的。

## 结果解释

- 输出几何覆盖输入与叠加图层共同涉及的空间范围（真并集）；线 × 面路径覆盖的是**源线的全长**，不产出叠加面。
- `source=input`：只被输入图层覆盖的分块。带输入侧字段值，叠加侧字段全为 NULL。
  线 × 面路径下指的是**落在所有叠加面之外**的线段片段，同样带着那条源线的整表字段、叠加侧字段全为 NULL。
- `source=both`：输入与叠加同时覆盖的分块。两侧字段值都带，且叠加侧取的是“生成这一块的那条叠加要素”的值。
  线 × 面路径下指的是**被某条叠加面盖住**的线段片段，叠加侧取的就是盖住它的那条叠加面的整表字段。
- `source=overlay`：只被叠加图层覆盖的分块。带叠加侧字段值，输入侧字段全为 NULL。线 × 面路径**不产出这一类**。
- 标记词表只有上面这三个值。早先在线 × 面路径上写的 `split` 已经退役（它同时指“被切开的内段”和“外段”，是含糊来源），
  那一路的片段现在按定义分别写 `both` 或 `input`。
- 普通路径的三类分块互不重叠，把 `input`/`both`/`overlay` 的面积相加就是并集面积。分块既可能是单面也可能是多面
  （例如叠加面的洞把输入几何切成两块时，相交块就是一个 MultiPolygon，它的面积是各部件之和），
  单面分块本身也可能带洞（外环 + 内环）。线 × 面路径判的是**长度**：片段长度相加等于源线全长。
- 上面的取值写在**标记列**里，标记列的默认名是 `source`。若输入或叠加字段本身就叫 `source`，
  那一列是用户的**数据列**（逐字保留、内容不变），标记列会按改名规则让位成 `source_2`（再冲突则 `source_3`…）：
  撞名时请按 `source_2` 这一列读上面的取值，取值含义完全不变。

## 适用场景

- 快速构造输入层与叠加层的合并覆盖范围
- 处理线状要素与面状范围的混合维度分段结果
- 在不关心原字段，只关心空间结果时生成统一结果图层

## 输出说明

- 输出图层名称固定为 `union`。几何类型：普通路径是 Unknown（分块既可能是面，也可能是多面）；
  线 × 面路径是 `MultiLineString`（输入是线 ⇒ 输出还是线，这一路不产出面要素）。
- 字段合并规则（**两条路径共用同一条规则**）：
  1. 先按输入图层原序写出全部输入字段；
  2. 再按叠加图层原序写出全部叠加字段，其中与输出表已有字段**同名（大小写不敏感）**的叠加字段自动改名为 `<name>_2`、`<name>_3` … 直到唯一。这条改名规则由本工具实现，GDAL 的 `OGR_F_FoundUniqueName` 不是公开 API；
  3. **数据列名一律逐字保留**：输入侧字段永远不改名（它们在原序第一位），两侧同名的情况只按上一条改叠加侧那一个；
  4. 末尾追加标记列，默认名 `source`（字符串）。它是本工具附加的列，因此**由它让位**：若输入或叠加字段里已经有 `source`，标记列按同一条改名规则取 `source_2`，再冲突继续 `source_3` …，用户的 `source` 数据列内容与名字都不动。
- 某一分块没覆盖到的另一侧字段一律留空（NULL）：`input` 块的叠加字段、`overlay` 块的输入字段都是 NULL。
  线 × 面路径同理 —— 面外的线段片段叠加侧字段全为 NULL；这一路只有线的片段，所以不会出现 `overlay` 块。
- 线 × 面路径的输出表与普通路径**同一条建表规则**（源字段 → 叠加字段 → 标记列），两侧字段都带；
  每条片段的叠加侧字段来自"盖住它的那条叠加面"，面外的片段那几列是 NULL。
- 输出格式建议使用 `.gpkg` 或 `.geojson`；用 `.shp` 时字段名会被 Shapefile 驱动截到 10 个字符，截断后同名的叠加列会建不出来（整列缺失），要保字段请优先用 `.gpkg`。
- 结果 metadata 的计数键（都是十进制字符串）：
  - `union_input_pieces`：`source=input` 的分块条数（线 × 面路径下面外的线段片段也算这一项）；
  - `union_overlap_pieces`：`source=both` 的分块条数（线 × 面路径下被叠加面盖住的线段片段也算这一项）；
  - `union_overlay_pieces`：`source=overlay` 的分块条数；**线 × 面路径恒为 0** —— 那一路不产出叠加面，
    这不是缺陷（见“算法内容”里线 × 面路径那一条），它的“不重不漏”由长度相加兜住；
  - `union_total_pieces`：输出总条数，等于前三项之和；
  - `union_skipped_overlay_pieces`：**只在大于 0 时出现**。叠加独有块因为几何运算失败而没写出去的块数，两种形态：
    候选输入几何的级联并集与逐条差集双双失败（一条都减不动），或级联并集成功但差集本身返回失败。
    这个键一旦出现就说明输出有缺口 —— 前三项之和小于应有的块数，分块面积相加**可能**小于并集面积
    （若被跳过的那块本来整块落在输入里，相加仍等于并集面积）；
    叠加几何“整个落在输入里”（差集结果为空）不算缺口，不记这一笔。

## 推荐输出文件名

- `union_result.gpkg`

## 注意事项

- **输出不能与 `输入文件` 或 `叠加矢量` 是同一个文件**（两个输入都进保护清单，按路径等价判定），否则在创建任何产物之前就失败
- 输入图层与叠加图层必须使用相同 CRS。
- 叠加图层中的非法几何会先尝试自动修复；**修复失败的单条被静默跳过**（既不报错也不计数，并集里就少那一块），只有全部叠加几何都被跳过时才整条失败。要核对产物是否少了块，请比 `union_total_pieces` 与预期，别指望这里报错。
- 两条路径都同时保留两侧字段（同名的叠加字段按上面的规则改名），线 × 面路径的属性按片段的归属叠加面取值。
- 只对“线 + 面”的混合维度做这项检查并拒绝执行，判据是**外包矩形两两相交的对数占比 ≥0.25**（且叠加几何 ≥3 条）：它测的是包框而非真实面积 ⇒ 互不重叠但包框相交的图层（斜置矩形、L 形地块）会被硬拒绝，而 3 条以上、包框互不相交但面积高度重叠的图层不会被拒绝。普通路径不做这项检查。
  线 × 面路径的片段归属（“这块片段取哪条叠加面的属性”）也建立在这道闸上：叠加面之间不重叠时最多只有一条面盖得住
  同一片段，取值唯一；哪天放开这道闸，同一片段会被两条面同时盖住，归属就得重新定义。
- 线 × 面路径**不产出叠加面**：输入是线、输出就是线，叠加面只用来切分线段和提供属性，不作为面要素写进输出图层。
- 几何为 NULL 的输入要素不写出，也不计入条数。
