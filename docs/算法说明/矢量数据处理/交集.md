# 矢量数据处理 / 交集

## 功能说明

提取输入图层与叠加图层共同覆盖的空间部分。

## 输入与输出

- 输入：
  - 输入矢量图层
  - 叠加矢量图层
- 输出：交集结果图层，建议使用 `.gpkg`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 主输入图层 |
| 输出文件 | 文件路径 | 是 | 无 | 交集结果输出路径 |
| 图层名 | 字符串 | 否 | 无 | 输入图层名 |
| 叠加矢量 | 文件路径 | 是 | 无 | 参与交集的第二个图层，默认取其第一个图层 |

## 算法内容

程序会先把叠加图层几何标准化，必要时尝试自动修复非法几何。普通情况下，对每个输入要素与叠加几何求空间交集；若输入是线、叠加是面，则先按叠加面边界切分线段，再只保留位于叠加面内的线段。输出只保留输入图层字段，不保留叠加图层字段。

## 处理流程

1. 打开输入图层和叠加图层。
2. 检查两者 CRS 是否一致。
3. 读取并标准化叠加图层几何。
4. 若叠加几何数量较少，先合并为整体叠加几何；否则按输入要素构造局部候选叠加几何。
5. 创建输出图层并复制输入字段。
6. 逐条处理输入要素：
   - 线 + 面时，先切分线，再保留位于叠加面内部的线段；
   - 其它情况直接计算交集几何。
7. 将非空交集写出。

## 结果解释

- 输出几何表示输入要素与叠加要素真正重合的空间部分
- 未相交的输入要素不会出现在结果中
- 输出属性全部来自输入图层
- 返回数量是成功写出的交集结果要素数
- 元数据键 `feature_count` 与返回数量同源（字符串形态）；另带 `action` / `input` / `output` 三个标准回显键；叠加输入被逐条丢弃时另发 `intersect_skipped_input_count`（>0 才出现，见“注意事项”）；其中"修复成功但维度降级（面修成线/点）"被丢的另发 `intersect_degraded_input_count`（>0 才出现，自 N158 起，与 skipped 键互斥）

## 适用场景

- 提取某区域内的道路、河流、地块等要素
- 找出两个专题图层真正重合的部分
- 从线要素中提取落在指定面范围内的有效片段

## 输出说明

- 输出图层名称固定为 `intersect`
- 输出字段沿用输入图层
- 结果几何类型以输入图层有效类型为主

## 推荐输出文件名

- `intersect_result.gpkg`

## 注意事项

- 输入图层与叠加图层必须使用相同 CRS
- 叠加图层的输入几何**被逐条丢弃的有四类**：输入本身就是 NULL 几何、克隆失败、克隆出来就是 EMPTY、
  以及非法且自动修复（`MakeValid`）失败或修成 EMPTY —— **只有最后这一类进过修复**，前三类不走修复也照样被丢掉。
  丢弃不报错、不中断（自 N148 起逐条计入 `intersect_skipped_input_count`，只在大于 0 时出现）；
  自 N158 起第五类：修复成功但维度低于输入（面修成线/点）同样被丢，计入 `intersect_degraded_input_count`
  （与 skipped 键互斥）；N158 之前这类几何会以降级后的线/点无痕混进产物，现在产物只含与输入同维的结果。
  后果：这个键出现 ⇒ 被丢掉的那条叠加面**参与不了求交**、交集结果少那一块，但动作**照样报 Success**、
  `feature_count` 照丢掉后的现实给（实测：叠加层 1 条有效面 + 1 条 NULL ⇒ `Success: Intersect completed: 0 features`
  同批里 `intersect_skipped_input_count: 1`）；只有叠加图层一条几何都没留下时才整条失败。
  核对：先查 `intersect_skipped_input_count`，再比 `feature_count` 与预期，别指望这里报错
- 同一刀（N158）还把**不经叠加采集器、直调同一标准化 helper 的其余动作**的退化输入从"修复后的线/点入产物"
  改为"按输入不可用丢弃"；本刀发键面只扩到叠加四动作，其余动作没有专用 degraded 键——boundary / centroid /
  convex_hull / envelope / interior_point / endpoints_extract / midpoints_extract / vertices_extract /
  singlepart / sliver_remove 十个动作的既有 `skipped_count` 会把这类丢弃一并计入（看该键变化即可诊断）；
  `duplicate_point_check` 有同族 `skipped_geometry_count` 但其图层闸只放点层、这类丢弃实际到不了；
  `adjacency` / `overlap_check` / `topology_check` / `dangling_endpoint_check` / `dissolve`
  键上无输入侧计数、丢弃静默，诊断只能对比改前改后的产物要素数或检查输出
  （逐动作登记见 `docs/RELEASE.md` 的 N158 节行为变更清单）
- **输出不能与 `输入文件` 或 `叠加矢量` 是同一个文件**（两个输入都进保护清单，按路径等价判定），否则在创建任何产物之前就失败
- 当前实现只保留输入字段，不会把叠加图层字段一并写出
