# 矢量数据处理 / 栅格化

## 功能说明

把矢量图层按指定分辨率烧写为单波段栅格。

## 输入与输出

- 输入：矢量图层
- 输出：单波段 `GeoTIFF` 栅格

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入矢量数据 |
| 输出文件 | 文件路径 | 是 | 无 | 输出栅格路径 |
| 图层名 | 字符串 | 否 | 无 | 要烧写的目标图层：留空 = 第一个图层；填了名字就**只烧该图层**，数据集里其余图层不参与烧写（N134，2026-10-22 改）。若该名字在本数据集里找不到、而数据集只有一个图层，则回退到那唯一的图层；否则返回 `Cannot find layer: <图层名>`。输出栅格的范围与投影也取自这同一层 |
| 栅格分辨率 | 浮点数 | 否 | `1.0` | 输出像元大小 |
| 属性字段 | 字符串 | 否 | 无 | 指定时把该字段值写入像元；该字段在目标图层里不存在则直接失败并返回 `attribute not found: <字段名>`；字段存在但类型不是数值型则直接失败并返回 `attribute field is not numeric: <字段名>`；留空则写入常数 `1` |

## 算法内容

程序先从目标图层读取外包范围；若指定了属性字段，先在目标图层里查该字段是否存在、再看它的类型是否为数值型（`OFTInteger`、`OFTInteger64`、`OFTReal` 三者之一），任一不满足就立即失败返回，此时输出文件尚未创建（N131、N132）。随后按分辨率计算输出栅格的行列数，创建一个 `Float32` 的单波段 `GeoTIFF`。之后调用 GDAL 的按图层栅格化过程（`GDALRasterizeLayers`），**只把上面选定的那一个图层**递交给烧写过程（N134）：数据集里未被点名的图层不再参与，输出栅格里不会出现它们的几何。若未指定属性字段，则所有落入几何范围内的像元写成 `1`；未覆盖区域填 `0`，并把 `0` 设为 `NoData`。

属性字段走的是 GDAL 的 `ATTRIBUTE=<字段名>` 选项（按图层栅格化过程吃 CPL 的 `NAME=VALUE` 选项表，不是命令行 `-a` 的 token 形态），取字段值的口径与烧常数 `1` 的口径互斥，一次调用只可能有一条成立。

烧值字段必须是数值型的原因：GDAL 的 `-a` 对文本域走的是"取字段值当 double 用"，文本会被静默转换（`"3"` 变 3.0）或转换失败（`"road_a"` 变 0.0），失败时动作照样报成功，产物却整幅是 `0` —— 而 `0` 正是本动作的 `NoData`，打开看不出异常。所以类型不合格的字段在调用栅格化之前就被拒掉。

## 处理流程

1. 打开输入矢量数据并定位目标图层。
2. 若指定了属性字段，先在目标图层里查该字段；查不到、或查到但类型不是数值型，都直接失败返回，此时输出文件尚未创建。
3. 读取图层范围。
4. 根据范围和分辨率计算输出栅格宽高。
5. 创建单波段 `Float32` 的 `GeoTIFF`。
6. 写入地理变换和投影。
7. 用 `0` 初始化整幅栅格，并把 `0` 设为 `NoData`。
8. 若指定属性字段，则按字段值烧写；否则按常数 `1` 烧写。
9. 只把上面定位到的那**一个**图层递交给 GDAL 的按图层栅格化过程生成结果（N134）。

## 结果解释

- 输出是单波段 `Float32` 栅格
- 被矢量覆盖的像元值来自属性字段或常数 `1`
- 未覆盖区域为 `0`，并被标记为 `NoData`
- 返回消息中的尺寸是实际生成的栅格大小
- 元数据键 `raster_width` / `raster_height`：实际生成的栅格列数与行数（字符串形态），与返回消息里的 `WxH` 同源，就是按范围和分辨率算出来的那两个数
- 元数据键 `source_feature_count`：**被烧写的那一层**的要素数（N134 起按被烧图层计，与烧写范围一致；改前按输入数据集全部图层求和，那是因为当时递交给烧写过程的就是整个数据集）。少数驱动不报缓存要素数时会现场遍历该层计数，缓存值取不到时也不会把 `-1` 当成 `0` 写进元数据
- 元数据键 `burn_field`：只在指定了属性字段时出现，回显的就是用户填的那个字段名，表示“像元值来自该字段”
- 元数据键 `burn_value`：只在属性字段留空时出现，固定为 `1`，表示“像元值是常数 1”
- `burn_field` 与 `burn_value` 互斥，一条产物只能说明一种烧值来源

## 适用场景

- 将行政区、地块、道路等矢量数据转成栅格参与像元级分析
- 为后续栅格运算准备掩膜图层
- 把分类编号或属性值写成像元值
- 将矢量边界转成规则网格输出

## 输出说明

- 当前实现固定输出为 `GeoTIFF`
- 输出范围来自输入图层外包矩形
- 输出投影直接继承输入图层坐标参考

## 推荐输出文件名

- `rasterize_result.tif`

## 注意事项

- 分辨率必须大于 `0`
- 输出尺寸由外包范围和分辨率直接计算，**像元总数上限是 5×10^8**：超出时动作**直接失败**（`Output raster too large (WxH = N pixels). Please increase resolution or reduce extent.`），且这道闸在建输出文件之前 ⇒ 不产出任何文件。上限之内才会生成很大的栅格
- `layer` 参数自 N134（2026-10-22）起真正限制烧写范围：**只烧点名的那一层，留空 = 第一层**。修复前该参数只用来读范围、读投影和校验属性字段，递交给栅格化过程的是整个数据集；而多图层的输入当时更在前一步就整条失败（`Rasterize failed: Neither -sql nor -l are specified, but the source dataset has not one single layer.`），即"其余图层一起烧"在多图层输入上从未发生过。因此这条变更的实际效果是：烧写范围收窄到点名层，同时多图层的输入从"整条动作失败"变成可用
- 多图层输入要烧别的图层就点名别的图层；想合并多个图层一起烧，本动作不做（得先把矢量并成一个图层）
- 属性字段的存在性校验按 `layer` 参数点名的那一层查；字段名大小写敏感（与 GDAL 的取域口径一致）
- 属性字段填了但不存在时不会产出任何文件（N131，2026-10-22 改）。修复前是先建好整幅 `0` 栅格、再由 GDAL 在烧写阶段报错，磁盘上会留一张全 `0` 的半成品 tif，而 `0` 恰是本动作的 `NoData`，打开也看不出异常
- 属性字段必须指向**数值型**字段（`OFTInteger` / `OFTInteger64` / `OFTReal`）：类型不合格时不会产出任何文件，直接返回 `attribute field is not numeric: <字段名>`（N132，2026-10-22 改）。修复前文本字段会被交给 GDAL 静默处理——非数值文本（如 `road_a`）整幅烧成 `0` 且动作报成功，数值形态的文本（如 `3`）则被静默转换成 `3.0`，两种都没有把用户点名的字段真正当数值用。校验只看类型，不做"非数值就退化成烧常数 `1`"的兜底
