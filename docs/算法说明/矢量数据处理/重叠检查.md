# 矢量数据处理 / 重叠检查

## 功能说明

分析同一面图层中存在面积重叠的要素对，并导出 CSV 结果表。

## 输入与输出
- 输入：面矢量数据
- 输出：CSV 检查结果

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | 输入矢量文件 |
| 输出文件 | 文件路径 | 是 | 无 | 输出 CSV 文件 |
| 图层 | 字符串 | 否 | 空 | 指定输入图层 |

## 算法内容

当前实现只支持面或多面图层，并且要求图层使用投影坐标系。程序会先缓存所有非空几何，再逐对判断两要素是否相交；只有真正存在面面积交叠时，才会输出结果。

这里的“重叠”不是简单的边界接触。实现会对相交要素求交集几何，并对交集结果计算**面积**，只有面积大于 0 时才认定为有效重叠；输出表中记录的是要素对及其重叠面积。

交面积口径与拓扑检查的 `overlap` 行**同源**：两者都调用同一个内部函数 `polygonIntersectionArea()`（`src/plugins/vector/vector_plugin_common.inc`），实现里**不再有第二份面积算法**。该函数按交集结果的类型取面积——面或多面直接取其面积；几何集合（`GEOMETRYCOLLECTION`）则累加其中所有子面与子多面的面积，集合里的线与点部分贡献 0。之所以必须处理几何集合：真实省界这类多面图层，相邻要素常常一边共面积、一边只共边，交集于是同时含面和线，GEOS 返回的就是这种混合维度集合。历史上本动作只认面与多面、集合一律算 0，于是同一对要素在重叠检查里报不出、在拓扑检查里报得出（挂账 N125，已修复）。

## 处理流程

1. 打开输入图层并检查几何类型是否为面或多面。
2. 检查空间参考是否为投影坐标系。
3. 读取全部非空几何，缓存 FID 和标准化后的几何。
4. 对缓存要素做两两组合检查。
5. 先用 `Intersects` 判断是否有相交可能。
6. 对相交要素求交集几何。
7. 用与拓扑检查同一个交面积函数算出交集面积：交集是面或多面时直接取面积；是几何集合时累加其中的子面与子多面面积，线/点部分按 0 计。
8. 仅当面积大于 0 时，输出 `source_fid,target_fid,overlap_area`。

## 输出说明

- 输出文件固定为 CSV，不是矢量图层。
- `overlap_area` 表示两个要素交叠部分的面积，单位跟输入图层坐标单位一致。
- 只会输出真正存在面积重叠的要素对。
- 纯边界接触、点接触或交集面积为 0 的情况不会写入结果。
- 交集同时含面与线（几何集合）时**照写**：面积只累加面部分，线部分贡献 0，只要面部分面积大于 0 就是一行重叠。若把这种交集算成 0，就会与拓扑检查的 `overlap` 行互相矛盾。

## 推荐输出文件名

- `重叠检查_result.csv`

## 注意事项

- 只支持面图层。
- 交面积口径与拓扑检查共用同一个实现函数，改一处会同时改两个动作；两者在真实省界上的行数关系由 `real_data_vector_full` 的省界臂互证。
- 建议在投影坐标系下使用，否则面积值不适合直接解读。
- 该工具只做检查，不会自动裁剪或修复重叠部分。

## 结果解释

- `overlap_area` 越大，说明两要素重叠范围越大。
- 如果结果为空，表示没有检测到面积重叠的要素对。
- 同一对要素只会输出一条记录，不会正反各写一次。

## 适用场景

- 地块、规划面、行政区等数据的质量检查。
- 合并数据源后排查重复入库或边界覆盖问题。
- 修复前先量化重叠问题规模。
