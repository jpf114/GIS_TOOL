# 地形分析 / 填洼

## 功能说明

为后续水文分析填平 DEM 中的洼地：每个像元被抬到"沿非降路径可达数据集出口的最低水面"——判据是**全局的**（以数据集边缘为出海口），不是像元自己的局部邻域极值。

## 输入与输出

- 输入：DEM 栅格
- 输出：填洼后的 DEM 栅格，建议 `.tif`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | DEM 输入 |
| 输出文件 | 文件路径 | 是 | 无 | 输出填洼结果 |
| 波段号 | 整数 | 否 | `1` | DEM 波段 |
| Z因子 | 浮点数 | 否 | `1.0` | 高程缩放系数 |
| 微坡度 | 浮点数 | 否 | `0.0` | 在洼地内部（严格低于水面的像元）叠加单调微坡，用于给填洼结果排出唯一流向；取值区间 `[0, 10]`，负值被钳到 0。数值是 `z_factor` 缩放后的，真实单位梯度为 `epsilon / z_factor` |

## 算法内容

填洼用于消除 DEM 中阻断水流分析的局部洼地，是很多水文分析前的预处理步骤。当前实现采用 **priority-flood**（Wang & Liu 2006）：把数据集边缘的像元作为出海口入队，用最小堆每次弹出"当前最低的已入队像元"，把它 8 邻域中尚未处理、且**严格低于**该出水面的高程抬到水面（指定 `微坡度` 时抬到"水面 + ε"），抬后的值再入队成为下一层像元的出水面。这样每个像元得到的是"沿非降路径可达数据集出口的最低水面"，一次求解即收敛。

换成这个算法的原因：原先的"重复若干轮、每像元取 3x3 邻域极值再取较大者"的不动点迭代，(a) 填不平平底洼地（坑内等高像元的邻域极值就是它自己），(b) 嵌套洼地要一层层往外爬，固定轮次上限会静默留下未填完的封闭汇，污染下游流向/汇流/流域分析。priority-flood 对平底与嵌套都是自然结果，且没有迭代上限这种隐式截断。

NoData 与 NaN 像元按**不可穿越的障壁**处理（不是出海口）：它们的存储值是哨兵（如 `-9999`）或无值，不代表地势低；自身不写回结果，输出保留原样。

## 处理流程

1. 打开输入 DEM 并读取指定波段。
2. 按 `z_factor` 对高程进行缩放。⚠ **输出不会把 `z_factor` 除回去**：填洼全程在缩放后的量上进行，`z_factor != 1` 时输出栅格的高程整体是"输入 × z_factor"（`2` 就是整幅翻倍）。要原单位请显式传 `1`，或事后自行除以 `z_factor`。
3. 构建 NoData 掩膜，并把 NoData / NaN 像元排除在淹没扩展之外。
4. 数据集边缘的有效像元作为出海口入队（最小堆，键为出水面高程）。
5. 每次弹出最低出水面，把 8 邻域中严格低于该水面的像元抬到水面（`微坡度 > 0` 时加 ε），抬后的值入队。
6. 堆空即全部像元处理完毕；恢复 NoData 位置并输出结果 DEM。

## 输出说明

- 输出结果为栅格文件。
- 建议优先使用 `.tif` 保存，便于后续在 CLI、GUI 或 GIS 软件中继续处理。

## 结果解释

- 输出是一个经过填洼处理的 DEM，而不是水流结果本身。
- 原本封闭或阻断流动的小型洼地会被抬平，更适合后续流向、汇流和流域分析。

## 适用场景

- 流向、汇流累积、河网提取、流域划分前的预处理。

## 推荐输出文件名

- `terrain_fill_sinks_result.tif`

## 注意事项

- 建议输入具有明确高程含义的 DEM 数据。
- 涉及距离、面积或坡度解释时，应确认坐标系与高程单位一致。
- `微坡度` 默认 `0`，此时填洼只做"抬到水面"的赋值，不引入任何额外高程改动；取非零值是为了让填平后的平底洼地也能排出唯一流向，代价是洼地内部像元被整体抬高 ε。
- `微坡度` 只作用于严格低于出水面的像元；原始值恰好等于水面、却被抬高后的水面漫过的像元（湖面上的岛、鞍部）也会拿到 ε，不放它就会重新出现封闭汇。
