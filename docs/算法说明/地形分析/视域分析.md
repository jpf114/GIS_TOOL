# 地形分析 / 视域分析

## 功能说明

以单个观察点为中心，计算 DEM 上的可视域范围。

## 输入与输出

- 输入：DEM 栅格
- 输出：视域结果栅格，建议 `.tif`

## 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入文件 | 文件路径 | 是 | 无 | DEM 输入 |
| 输出文件 | 文件路径 | 是 | 无 | 输出视域结果 |
| 波段号 | 整数 | 否 | `1` | DEM 波段 |
| 观察点X | 浮点数 | 否 | `0.0` | 观察点 X 坐标；不填按 `0` 计算（多半落在数据范围外，结果会是"全部不可见"），实际使用必须显式给出 |
| 观察点Y | 浮点数 | 否 | `0.0` | 观察点 Y 坐标；同上 |
| 观察高度 | 浮点数 | 否 | `2.0` | 观察点高度，必须大于等于 0 |
| 目标高度 | 浮点数 | 否 | `0.0` | 目标高度，必须大于等于 0 |
| 最大距离 | 浮点数 | 否 | `0.0` | 最大分析距离，`0` 表示不限 |
| 曲率折射系数 | 浮点数 | 否 | `0.85714` | 地球曲率与大气折射合并系数（GDAL 默认值）；`0.0` 关闭修正，取值区间 `[0, 2]`。批次 A 之前该修正不启用 |

## 算法内容

视域分析用于判断从单个观察点出发，DEM 上哪些位置在地形遮挡条件下可见。当前实现直接调用 GDAL 的 `ViewshedGenerate` 流程完成分析，因此结果语义与标准视域分析流程一致。

默认启用的曲率/折射修正把距离换算成高程差（Δz ≈ coeff·d²/2R，R 以米计），所以**它要求输入 CRS 是投影坐标系**：
地理坐标系（或没有 CRS）时距离是"度"，Δz 恒为 0，修正会静默失效。⇒ 这种情况下动作仍然成功，但会给出告警：
`metadata` 里的 `crs_warning` 与结果消息尾部都写 `observer analysis expects projected CRS`。看到它，请先把 DEM 投到米制投影再重跑。

启用修正后远距可见性会明显收紧（实测同幅平坦 DEM、`max_distance=30 km`、观察高 10 m：可见像元 2819 → 517），
这不是精度微调，而是与批次 A 之前的结果**不同**；需要旧行为时把 `curvature_coeff` 传 `0.0`。

## 处理流程

1. 打开输入 DEM 并检查指定波段。
2. 读取观察点坐标、观察高度、目标高度和最大分析距离。
3. 调用 GDAL 视域分析流程，以当前波段作为高程输入。
4. 按观察点和地形遮挡关系计算每个像元是否可见。
5. 将生成的视域结果写出为单波段栅格。

## 输出说明

- 输出结果为栅格文件（单波段 Byte 可见性掩膜）。
- 建议优先使用 `.tif` 保存，便于后续在 CLI、GUI 或 GIS 软件中继续处理。
- **输出声明了 `NODATA = 0.0`** ⇒ "不可见"像元同时也是 NoData，渲染链路会把不可见当透明。
  想区分"不可见"与"真正无数据"，请以高程源本身的 NoData 为准（先看 DEM，再看视域掩膜），不要只看输出的 nodata 标记。
- "被遮挡"与"超出 `max_distance`"写入的是同一个值（`0.0`），**在输出里不可区分**。

## 结果解释

- 当前实现会生成标准视域结果栅格，可见区域与不可见区域对应不同像元值。
- 结果依赖 DEM 精度、观察点位置和高度设置。
- 如果设置了 `max_distance`，分析范围会被限制在该距离内。
- 本动作（单点）默认做曲率/折射修正，而**多点视域不做**（其系数仍为 `0.0`）⇒ 同幅 DEM 上两个视域动作的结果**不可直接比较**。

## 适用场景

- 通视分析、站点布设、景观可视范围估计。

## 推荐输出文件名

- `terrain_viewshed_result.tif`

## 注意事项

- 建议输入具有明确高程含义的 DEM 数据。
- 涉及距离、面积或坡度解释时，应确认坐标系与高程单位一致。
