# GIS TOOL 架构设计文档

## 1. 概览

GIS TOOL 是一个面向 Windows 的插件式 GIS / 遥感算法工作台，提供 CLI 和 GUI 双入口，底层共享同一套算法插件执行链。

当前版本定位：

- 聚焦算法工作台，而不是地图展示平台
- 统一封装多类 GIS / RS 算法
- 通过参数模型复用 CLI、GUI 和测试入口
- 通过任务中心、回归测试和发布验收提高可交付性

## 2. 技术栈

| 组件 | 技术 | 说明 |
| --- | --- | --- |
| 语言 | C++17 | 核心实现语言 |
| 构建系统 | CMake | Debug / Release 双构建目录 |
| 依赖管理 | vcpkg manifest | 仓库内锁定依赖版本 |
| GIS 核心 | GDAL | 栅格、矢量、元数据、坐标系统 |
| 计算机视觉 | OpenCV | 图像处理、匹配、分类等 |
| 坐标投影 | PROJ | CRS / EPSG 相关能力 |
| GUI | Qt 6 Widgets | 图形界面、任务中心、离屏自检 |
| 测试 | Google Test + CTest | 单测、集成、GUI offscreen 回归 |

## 3. 设计原则

1. 插件隔离：每个主功能域通过独立插件暴露动作能力。
2. 三层共用：GUI、CLI、测试最终都落到同一套插件执行路径。
3. 参数驱动：参数定义是 GUI、CLI、文档和校验逻辑的共同基础。
4. 可回归：共享测试数据、离屏回归和真实数据专项回归。
5. 可交付：Debug / Release、安装态 smoke test、归档文档和发布文档保持一致。

## 4. 分层结构

```text
GUI / CLI
  -> framework
  -> plugins
  -> core
  -> GDAL / OpenCV / PROJ / Qt
```

### 4.1 core

`core` 层负责底层能力封装，主要包括：

- `gdal_wrapper.*`：栅格/矢量读写、CRS、元数据
- `opencv_wrapper.*`：影像矩阵与算法辅助
- `progress.h / progress.cpp`：进度、日志、取消检查接口
- `runtime_env.*`：插件目录、资源目录与运行时路径
- `block_processor.*`：栅格分块处理
- `logger.*`：统一日志记录与导出
- `perf_monitor.*`：耗时记录与性能数据导出
- `spindex_presets.*`：光谱指数预设表达式

### 4.2 framework

`framework` 层定义插件协议、参数模型和运行时基础设施。

关键对象：

- `IGisPlugin`
  - 暴露插件名、显示名、描述、版本、参数定义和执行入口
- `ParamSpec`
  - 描述参数键名、显示名、类型、是否必填、默认值、范围和枚举值
- `ParamValue`（定义于 `param_spec.h`）
  - 承载实际参数值，与 ParamSpec 配套使用
- `Result`
  - 统一承载执行结果、输出路径、元数据和取消状态
- `PluginManager`
  - 负责发现、加载和注册插件
- `WorkflowRunner`
  - 将多个插件动作串成预设工作流
- `action_validation.h / action_validation.cpp`
  - 动作参数校验，在执行前对参数进行合法性检查与约束验证

### 4.3 plugins

当前主插件包括：

- `projection`
- `cutting`
- `matching`
- `processing`
- `classification`
- `georef`
- `terrain`
- `spindex`
- `vector`
- `raster_manage`
- `raster_inspect`
- `raster_render`
- `raster_math`

其中 `raster_manage / raster_inspect / raster_render / raster_math` 在 GUI 中归并为“栅格工具”，CLI 中仍保持独立插件名。

## 5. 数据与执行链路

统一执行链路如下：

```text
用户输入
  -> ParamSpec 定义
  -> GUI / CLI 收集参数
  -> ParamValue
  -> plugin.execute(...)
  -> Result + outputPath + metadata
```

这条链路的意义是：

- GUI 不单独维护一套算法逻辑
- CLI 不单独维护一套参数规则
- 测试可以直接压到同一执行面

## 6. GUI 架构

GUI 的角色不是地图平台，而是算法工作台外壳。

主要组成：

- 左侧主导航
  - 按能力域组织主功能与子功能
- 执行页
  - 功能说明
  - 输入 / 输出 / 高级参数卡片
  - 批处理控制
  - 执行状态与结果摘要
- 结果预览页
  - 栅格、矢量、统计结果的基础预览
- 任务中心页
  - 任务列表
  - 日志查看
  - 重新执行 / 编辑参数 / 删除 / 清空
- 辅助组件
  - `WelcomeDialog`
  - `ProgressDialog`
  - `TaskCenterPage`
  - `QtProgressReporter`
  - `TaskManager`：任务管理器，负责任务的创建、调度与生命周期管理
  - `TaskDatabase`：基于 SQLite 的任务持久化存储
  - `ExecuteWorker`：后台执行工作线程，将算法执行移出 UI 线程
  - `NavPanel`：左侧导航面板，按能力域组织功能入口
  - `SettingsManager`：设置管理器，统一读写应用配置
  - `CustomIndexPresetStore`：自定义指数预设存储，管理用户自定义光谱指数
  - `CrsDialog`：坐标参考系统选择对话框
  - `WorkflowPage`：工作流页面，串联多步骤处理流程
  - `ResultPreviewPage`：结果预览页，展示执行结果概览
  - `RasterPreviewWidget`：栅格结果预览组件
  - `VectorPreviewWidget`：矢量结果预览组件
  - `StatsPreviewWidget`：统计结果预览组件

GUI 的关键机制：

- 参数自动推导：输出路径、部分表达式、图层名、范围等
- 结果预览：执行成功后可在 GUI 内查看部分处理结果
- 批处理：可对目录内文件按统一动作串行提交任务
- 取消与重试：任务支持取消，请求会沿统一取消链下传；批处理任务支持有限重试

## 7. CLI 架构

CLI 提供稳定、可组合的脚本化入口。

典型形式：

```powershell
gis-cli <plugin> <action> --input <path> --output <path>
```

CLI 负责：

- 插件发现与加载
- 参数解析与必填校验
- 动作分派
- 执行结果输出

CLI 与 GUI 共用同一套插件参数和执行逻辑，因此功能补齐时通常优先补插件层，而不是分别补两个入口。

## 8. 线程与任务模型

### 8.1 GUI

GUI 采用“界面线程 + 后台任务执行”的模式：

- 主线程负责交互、状态展示与任务管理
- 算法执行放入后台任务
- 进度和日志通过 `ProgressReporter` 回传

### 8.2 任务中心

任务中心围绕以下目标建立：

- 串行、可追踪的任务执行
- 明确的任务状态
- 可查看日志和耗时
- 可重提任务

### 8.3 取消链路

取消不是 UI 假动作，而是贯穿执行链的真实状态：

- GUI 发出取消请求
- `ProgressReporter` 暴露取消检查入口
- 插件内部周期性检查取消状态
- 取消后返回结构化 `Result::cancelled(...)`

### 8.4 进度节流

为避免高频进度刷新拖慢 GUI，`QtProgressReporter` 对进度更新做节流处理，只在关键时机或达到阈值时推送更新。

## 9. 工作流与元数据

### 9.1 预设工作流

当前工作流能力用于串联常见处理步骤，内置方向包括：

- 遥感预处理
- 地形分析
- 变化检测

### 9.2 处理元数据

输出结果会附带处理元数据，便于追溯：

- 插件名
- 动作名
- 插件版本
- 时间戳
- 关键输入参数

相关元数据写入 `GIS_PROCESSING` 域，用于结果溯源和验收辅助。
