# GIS TOOL 架构设计文档

## 1. 概述

GIS TOOL 是一个基于 C++17 构建的跨平台 GIS 算法工具台，采用插件化架构，提供 CLI（命令行界面）和 GUI（图形用户界面）双入口，底层共享同一套算法插件引擎。

### 技术栈

| 组件 | 技术 | 版本 |
|------|------|------|
| 语言 | C++17 | — |
| 构建系统 | CMake | ≥3.16 |
| 包管理器 | vcpkg | — |
| GIS 核心 | GDAL | 3.12.3 |
| 计算机视觉 | OpenCV | 4.x |
| 坐标投影 | PROJ | 9.x |
| GUI 框架 | Qt | 6.x（Widgets + Svg） |
| 测试框架 | Google Test | 1.x |
| 图标库 | Phosphor Icons | Bold + Regular |
| 当前版本 | v0.6.0 | — |

### 设计原则

1. **插件隔离**：每个算法模块封装为独立动态库，通过统一接口加载
2. **三层共享**：底层算法、CLI、GUI 共享同一套参数-执行-结果体系
3. **参数驱动**：所有算法的输入输出参数统一由 `ParamSpec` 描述，`ParamValue` 承载。`ParamSpec` 同时是 CLI、GUI 和文档的参数元数据权威来源，三者必须保持一致。
4. **进度可观测**：所有算法通过 `ProgressReporter` 接口回传进度和消息
5. **可测试性**：支持离屏 GUI 回归测试和真实数据专项回归

### 2.2 框架层 (framework)

定义插件系统的核心抽象和运行时基础设施。

#### 2.2.1 插件接口 (IGisPlugin)

```cpp
class IGisPlugin {
public:
    virtual std::string name() const = 0;           // 插件唯一标识
    virtual std::string displayName() const = 0;    // 中文显示名
    virtual std::string description() const = 0;    // 功能描述
    virtual std::string version() const = 0;        // 版本号
    virtual std::vector<ParamSpec> paramSpecs() const = 0;  // 参数定义
    virtual Result execute(
        const std::map<std::string, ParamValue>& params,
        ProgressReporter& progress) = 0;            // 执行入口
};
```

#### 2.2.2 参数系统 (ParamSpec / ParamValue)

参数系统是三层共享的核心设计。每种算法参数通过 `ParamSpec` 静态声明，通过 `ParamValue` (std::variant) 动态承载。

**ParamType 枚举：**

| 类型 | 说明 | ValueType |
|------|------|-----------|
| `Enum` | 枚举字符串 | `std::string` |
| `FilePath` | 文件路径 | `std::string` |
| `CRS` | 坐标参考系 | `std::string` |
| `Int` | 整数 | `int` |
| `Double` | 浮点数 | `double` |
| `String` | 通用字符串 | `std::string` |
| `Extent` | 空间范围 | `std::array<double, 4>` |

**ParamSpec 结构：**
- `key` — 参数键名（全局唯一）
- `displayName` — GUI 显示名
- `description` — 参数说明
- `type` — 参数类型
- `required` — 是否必填
- `defaultValue` — 默认值
- `minValue / maxValue` — 数值范围约束
- `enumValues` — 枚举可选值列表

#### 2.2.3 执行结果 (Result)

```cpp
struct Result {
    bool success;
    bool isCancelled;
    std::string message;
    std::string outputPath;
    std::map<std::string, std::string> metadata;

    static Result ok(const std::string& msg = "", const std::string& output = "");
    static Result fail(const std::string& msg);
    static Result cancelled(const std::string& msg = "操作已取消");
};
```

#### 2.2.4 插件管理器 (PluginManager)

负责从指定目录加载动态库（.dll / .so），通过导出函数 `GIS_PLUGIN_EXPORT` 实例化插件对象。

```
加载流程：

```

## 3. 数据流

### 3.1 执行链路

```
用户交互 → ParamSpec 声明 → 参数收集 → ParamValue → execute() → Result
     ↑                                                                    ↓
  GUI/CLI 入口                                                      metadata +
                                                                   outputPath
```

### 3.2 GUI 参数自动推导

GUI 实现了智能参数推导机制 (`syncDerivedParams`)：
- **输出路径自动填充**：根据输入文件路径自动生成带后缀的输出路径
- **表达式自动带入**：选择 `preset` 后自动填充 `expression` 字段
- **图层自动检测**：读取输入文件元数据自动填充默认图层名
- **范围自动填充**：读取输入栅格的地理范围自动填充 `extent`

### 3.3 进度报告链路

```
Plugin::execute()
    → ProgressReporter::onProgress(percent)
    → QtProgressReporter (信号桥接 + 进度节流)
    → QProgressBar 更新
    → QStatusBar 更新
```

进度节流机制：`QtProgressReporter` 内置节流逻辑，避免高频信号导致 GUI 卡顿：
- 增量阈值：进度变化 ≥ 1% 时强制发射
- 时间间隔：距上次发射 ≥ 50ms 时强制发射
- 关键更新：首次、完成（1.0）、重置后强制发射

### 3.4 取消链路

```
用户点击取消
    → QtProgressReporter::cancel() (设置 atomic<bool>)
    → 插件内部 progress.throwIfCancelled() 检查
    → 抛出 CancelledException
    → ExecuteWorker 捕获 → Result::cancelled()
    → MainWindow 更新 UI 为取消状态
```

协作式取消机制：
- `CancelledException`：继承 `std::runtime_error`，统一取消异常类型
- `ProgressReporter::throwIfCancelled()`：轻量取消检查入口，已取消时抛出异常
- `Result::cancelled()` + `isCancelled` 字段：结构化取消结果，替代字符串匹配
- 所有 13 个插件、39 个文件、461 处取消检查已接入

## 6. 线程模型

### GUI 线程
- **主线程**：Qt 事件循环，负责 UI 渲染和交互
- **工作线程**：每次执行创建 `QThread` + `ExecuteWorker`
- **任务队列**：`TaskRunner` 维护 `QQueue<QueuedTask>`，串行执行任务，前一个完成后自动启动下一个
- **进度线程安全**：`QtProgressReporter` 通过 Qt 信号槽机制跨线程更新 UI，内置进度节流
- **取消机制**：协作式取消，插件通过 `throwIfCancelled()` 检查取消状态

### 任务管理系统

GUI 侧实现了三层任务管理架构：

| 组件 | 职责 |
|------|------|
| `TaskRunner` | 任务队列调度，串行执行，信号桥接 |
| `TaskManager` | 任务生命周期管理，提交/完成/删除/日志 |
| `TaskDatabase` | SQLite 持久化，按 displayGroup 分库，WAL 模式 |
| `TaskCenterPage` | 任务列表 + 日志显示 UI，支持重新执行/编辑/删除 |

**任务执行流程：**
```
用户点击执行 → TaskRunner::run() → 入队 → processQueue()
    → startTask() → QThread + ExecuteWorker → 插件 execute()
    → finished 信号 → finishTask() → 计算耗时 → 更新数据库
    → processQueue() → 处理下一个排队任务
```

**数据库设计：**
- 存储路径：`<exe_dir>/task_data/gis_tasks_<group>.db`
- 主表 `tasks`：id, plugin_name, action_key, params, status, result_msg, start_time, end_time, duration_ms
- 日志表 `task_logs`：id, task_id, timestamp, level, message
- 自动清理：数据库超过 50MB 时删除已完成的历史任务

**批量处理：**
- GUI 执行控制卡片提供"批量处理"复选框
- 用户选择输入目录和文件过滤条件（如 `*.tif`）
- 系统自动为每个匹配文件创建独立任务并提交到队列
- 输出路径自动推导：`<原文件名>_<actionKey>.<后缀>`

**耗时统计：**
- `TaskRecord.durationMs`：毫秒精度计时，从任务提交到完成
- 存储于 SQLite `duration_ms` 字段
- GUI 结果摘要和任务中心均显示耗时

**错误人性化：**
- `localizeResultMessage()` 将英文结果消息翻译为中文
- 20+ 条已知成功消息的中文映射
- 6 类常见错误（文件不存在、权限不足、内存不足、波段不存在、格式不支持、操作取消）附带建议

### CLI 线程
- 单线程执行，通过命令行参数触发后直接调用插件 `execute()`

### 8.2 离屏回归机制

GUI 离屏回归使用 `-platform offscreen` 模式：
1. 生成合成测试数据（gui_test_data_helper）
2. 通过 `--select-plugin` / `--select-action` / `--set-param` 注入参数
3. 通过 `--auto-execute` / `--quit-on-finish` 自动执行并退出
4. 校验输出文件和状态码
