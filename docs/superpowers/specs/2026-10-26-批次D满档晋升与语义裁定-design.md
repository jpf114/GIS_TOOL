## 2. 本轮已定的三条裁定（用户 2026-10-26）

1. **按数据可达性分两档晋升**（不是"全部按 vector 同档"，也不是"只做夹具判据"）：
   本机有真实输入可喂的动作走满档（夹具数值判据 + 真实数据腿 + 存活变异取证）；
   没有真实输入的只做夹具判据 + 变异取证，真实腿**如实登记"本机无对应数据，不建"**，
   不拿合成图冒充真腿，也不把"合成夹具跑过了"写成"真实数据覆盖"。
2. **三条需要产品拍板的挂账逐条拍、允许改已发布动作的可观测行为**（N137 / N149 / N150）。
   流程固定为：先实测取证 → 控制器给推荐方案与影响面 → 用户拍 → 才动 `src/`。
3. **GUI 深化验证继续延后**；**"干净机器"端到端实测不纳入批次 D**（`install_smoke` 的裸环境模拟维持现状口径）。

**非射程（沿用批次 C 的既有裁定，批次 D 不自行翻案）**：不在产品二进制里引入失败注入缝

## 4. 关键机制（照抄批次 C 已验证的规矩，不重新发明）

1. **三层判据下限**：夹具期望值 + 真实腿关系式断言 + 存活变异取证；"旧臂绿 / 新臂红"是唯一取证模板（R-B16）。
2. **晋升批的旧臂回退**必须三件一起：测试文件 + 登记表行 + `kPendingCeiling`，否则
   `CoverageMeta.GoldEvidenceIsAuditable` 会拿新登记表审旧测试块，红在与变异无关的地方。
3. **禁止子串包含式数字判据**（`Contains("键: 短数字")` 会被长数字前缀吃 ⇒ 假绿发生器）。
4. **真实腿判据必须是关系式且成对**（数据相关的期望值一律不钉死；"任何动作在真实数据上恰好报 0"
   先跟口径相近的另一个动作对撞一次再决定怎么写）。
5. **defended ≠ exercised、exercised ≠ conformant**：产物合规类判据要引第二个客户端（`ogrinfo -so -al -spat`）
   交叉验证；引"读端返 0"当证据前必须先打 Extent 证包框覆盖数据。
6. **新增真实腿的 TIMEOUT ≥4× 起步**；腿跌破 2.5× 先归因再拆腿（固定开销 `Ensure-*` 会被拆腿翻倍）。
7. **双树全量是控制器的收口门**，不写进任何下级任务书；派发消息会被截断 ⇒ 判据要求与"报告即日志"只能落 brief 文件。
8. **任务书尺寸**：一个变异一条派、取证派不兼实现与全量、同形状批量单派 ≤20 条（批次 C 三次撞 150 回合的教训）。
