### 1.6 依赖版本口径复核（2026-10-14 vcpkg 升级后）

## 2. 目标与全局验收口径

1. **无静默错误结果**：任何参数错误、表达式非法、GDAL/算法失败必须走 `Result::fail` 或非 0 退出码，禁止"成功 + 错误数据"；
2. **用户数据不可被静默破坏**：输出==输入必须有守卫；预设/历史/源文件不得被静默覆盖或删除；
3. **算法口径对齐行业标准**（批次 B）；
4. **崩溃安全**：所有跨线程执行路径有异常兜底与生命周期收口；
5. **可编译可验证**：HEAD 干净构建 + 全量 ctest 绿 + 每 action ≥1 数值金标用例 + 测试数据三态（CRS/NoData/符号量级/类型）齐备 + 无"跳过即通过"；
6. **GUI 与 CLI 契约一致**：同一 action 的必填集合与默认值跨入口一致；
7. 交付合规：干净机器可运行（运行库）、许可文本随包、无用户可见乱码。

### 12.1 拍板后的施工次序建议

1. **先补锁、再改值**。本片实测出六条"改了之后既有用例全绿"的推荐支：`G-D`、`N29`、`N40`、`N41`、`N44/N45`、`N46`。⇒ 这六条**每条都必须先补能红的断言**（否则改错也没人知道），补锁与改值可以同批提交，但锁必须先红一次。
2. **必须同批**：`G-A` + `G-B`（同一段 `spindex.custom_index`；`G-A` 的 4 条既有红要同批改期望值，`G-B` 的 1 条要同批把夹具改成 ≥6 波段）；`N44/N45` + `N46` + `N43`（都在 `terrain_plugin.cpp` 的两个视域函数与本地写出器上，分开做会互相冲突）。
3. **必须分开**：`G-C`（只碰 CMake，与运行期无关，可最先做且零风险）；`N31`（`raster_manage`）；`N34`（`classification`，且它应当并进 `N93` 的 NoData 判据统一，不单独立项）；`N40`（`fill_sinks`，文件同 `N44` 但函数不同，且要先定"产物是否回除 z_factor"）。
4. **建议次序**：`G-C` → 六条"补锁"（先写断言，红一次）→ `G-A`+`G-B` → `N43`+`N44/N45`+`N46` → `N41` → `G-D` → `N40` → `N31` →（`N93` 落地时一并）`N34`。
5. 三条跨行的前置裁定必须**先于**上述施工：① `fill_sinks` 产物是否回除 `z_factor`（`N40`）；② 类别/掩膜产品是否改用整型 dtype（`N43` 的 A2）；③ `GUI_BUILD_GUI=OFF` 构型下 `install_closure` 的处置（`G-C`）。

### 12.2 本片发现的工单骨架错误与台账失真（直接指）

- **`N29` 的推荐理由不成立**：骨架写"新引擎已在 `gis_core`"，但该引擎的 `Op` 只有 `+ - * / Negate`，**没有比较/逻辑运算**，`cond` 的语法无法用今天的引擎表达。A 不是"迁移"，是"给核心引擎扩语法"。
- **`N31` 的候选 A 少了半个判据**：骨架只写"显式失败"，未提"整波段 NoData 必须豁免"；一刀切会打红 Task 7 刻意支持的 `ProximityAllNoDataBandWritesItsNoDataInsteadOfTheSentinel`。
- **`N40` 的候选 B 缺前提与实现的符号**：未提"产物本身乘了 z_factor、没有回除"，也未说明真实单位对应的实现是 **×z_factor**（写成 ÷z_factor 会把真实梯度再缩 1/z²）。
- **`G-D` 的候选 B 缺配套**：只改匹配端会让 `bandMax` 落进"未匹配"；规则生成端的最后一类必须闭合。
- **台账对 `N45` 的"现状锁"描述与盘上不符**：`EXPECT_TRUE(single.noDataDeclared)` 不存在（只有采集与 multi 侧的 `EXPECT_FALSE`）。
- **行数口径**：骨架表实际是 **24 个表格行 / 27 个编号**，与本片任务书"23 条"及"B19b 11 条"（该清单实列 12 个）两个数字都对不上；本片按任务书取前 12 行，剩余 12 行交 B19b。
- **`G-C` 的"可能可在 Phase II 提前做"已过期**：Phase II 已结案（B4/B5 交付），`-DGIS_BUILD_GUI=OFF` 今天仍 RC=1。
