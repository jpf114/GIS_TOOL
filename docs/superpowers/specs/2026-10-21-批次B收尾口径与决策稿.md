## 1. N103 补充：生产态 `GIS_TOOL_SETTINGS_INI` 残留会发生什么

用户可见的那一句落在 [RELEASE.md](../../RELEASE.md) 的"批次 B 发布说明 → 用户设置存储位置"一节；
本节记机制与行号（都是现读，`src/gui/app_settings.cpp`）。

| 事实 | 依据（现读） |
|---|---|
| 变量只要**非空**（含只有空格）就算"注入态"：不做 `trim()`，判据故意宽松 | `settingsOverrideActive()`，`:200-212` |
| 注入态下设置文件路径**直接取变量值**，用户真实 ini（`%LOCALAPPDATA%\GIS\GIS Tool\settings.ini`）不再被读写 | `resolvedSettingsPath()`、`appSettingsPath()`，`:214-225` |
| 迁移被**门控整段跳过**（返回 0，一条旧源都不打开） | `migrateLegacySettingsGated()`，`:190-198` |
| 被跳过的启动**不写一次性标记** ⇒ 之后每次启动都会重试迁移（每次只是一次早退） | `migrateLegacySettingsFrom()`，`:180-187` |
| 没有任何日志/诊断：拒绝与"未接上"共用同一条"跳过"路径 | `:169-179` |

**"每启动重置"这句只在变量指向瞬时路径时成立**：变量指向一个**固定**文件时，设置会持久化在那个文件里，
不会每次启动清空。可复现的后果是上面两条——设置库整体换落点、迁移每启动重试且无诊断。
不要把它写成"每次启动必然丢设置"。

**为什么不在拒绝层加日志**：这两条生产臂每一轮回归都会被用例正常触发两次
（`AppSettingsLegacySources.ProductionArmsRefuseToOpenWhileOverrideActive`）⇒ 加日志等于恒假警报。
要加只能加在门控层（`migrateLegacySettingsGated` 的 `if (overrideActive) return 0;` 处），
用"注入态/生产态"区分；这是已知、可接受、本批不动的行为。

## 6. 决策稿：B17 乱码检测器是否落成 ctest

### 6.1 现状

- 检测器 `build/tmp/detect_mojibake.py`（163 行 / 5336 B，`build/` 被 gitignore ⇒ 不进版本库），
  两条规则：①GBK roundtrip（带"解码结果必须含 CJK 连续串"的假阳性守卫）；②Unicode 私用区 U+E000–U+F8FF。
  B17 两轮共修 **28 行**（13 行 roundtrip + 15 行 PUA）。
- B17 报告已写明当时不做成 ctest 的理由：一次性归零已够、给两棵树各 +1 注册用例、引入 Python 依赖。

### 6.2 建议：落库，但按独立任务做

- **收益一句**：今天没有任何提交期防线——同类乱码再长出来只能靠人眼或临时脚本发现；落成用例后，
  `src/`/`tests/`/`docs/` 一旦出现 roundtrip 或 PUA 乱码，两棵树在跑测时就红。
- **成本一句**：每棵树 +1 条注册用例（692→693 / 690→691）、对 Python 的调用依赖（本机 `python3` 是空壳，
  必须写 `python`；CI 需探测解释器，找不到就 SKIP 而不是假绿）、扫描约 570 个文件（秒级）。
- **必须带的三个前提**（否则就是"窄规则 0 ＝ 假绿"）：
  1. 规则族要齐：roundtrip、PUA，**再加 U+FFFD（替换字符）**——B17 已点名它是本族缺的一条；
  2. **正例夹具**：仓库内放一小段已知乱码样本，断言检测器能命中（证明规则能红）；
  3. 假阳性守卫要保留：`未知` 这类合法中文的 GBK 字节恰好是合法 UTF-8（解成希腊字母），
     不守会多出 10 条假阳性。
- 结论：**建议落库**（含夹具与解释器探测），但不在 B20a 实施——它要新增文件与 ctest 注册，
  超出"只改 docs"的范围。
