**Interfaces:**
- Consumes: 无（本任务是叶子）。
- Produces（`namespace gis::gui`，头文件 `src/gui/app_settings.h`）：
  - `QSettings appSettings();` —— 返回按下面的裁定解析好路径的 `QSettings`（IniFormat）。
  - `QString resolvedSettingsPath(const QString& overrideValue);` —— **纯函数**，不读环境变量、不建 `QSettings` 对象、
    不落盘。`overrideValue` 非空 ⇒ 原样返回；为空 ⇒ 返回 `QDir(AppConfigLocation).filePath("settings.ini")`。
    存在理由见 R-B2b（断"生产路径形状"必须走它，否则测试会写真人的 `%LOCALAPPDATA%`）。
  - `QString appSettingsPath();` —— `resolvedSettingsPath(QString::fromLocal8Bit(qgetenv(...).constData()))`，只算路径。
  - `bool settingsOverrideActive();` —— `GIS_TOOL_SETTINGS_INI` 是否非空。
  - `int copyMissingKeys(const QSettings& from, QSettings& to);` —— 把 `from` 里有、`to` 里没有的键复制过去，返回复制条数。**纯函数，不碰注册表**。
  - `constexpr const char* kMigrationMarkerKey = "meta/migrated_from_registry";`
  - `int migrateLegacySettings(QSettings& target);` —— 见 Step 5 的门控语义。

**Rulings（先读完再写代码）**
- **R-B1**：落点用**显式路径**构造，不依赖 Qt 的 org/app 默认解析：
  `QStandardPaths::writableLocation(QStandardPaths::AppConfigLocation)` + `"/settings.ini"`
  ⇒ 在 Windows 生产进程（org `"GIS"`、app `"GIS Tool"`，见 `src/gui/main.cpp:36-37`）下即
  `%LOCALAPPDATA%\GIS\GIS Tool\settings.ini`。选它而不是默认路径的理由：路径可在测试里断言、且不受 `setPath()` 全局副作用影响。
- **R-B2**：`GIS_TOOL_SETTINGS_INI` **优先级最高**，且**一旦非空就完全跳过注册表导入**。
  WHY：否则每个测试进程都会去读真实 `HKCU`，测试结果依赖开发者机器状态（不可复现），且导入会把用户数据写进测试 ini —— 直接违反"测试不得写真实用户状态、也不得读它当输入"这条红线。
- **R-B3**：导入源用 `QSettings` 对象本身表达（`QSettings("GISTool","GISTool")` 与默认构造那两个旧落点），
  **不在 C++ 里硬编码注册表路径字符串**。Qt 的 org/app→键路径映射不是本仓的职责，用旧对象读它天然正确、也天然跨平台。
- **R-B4**：迁移只做"**补缺不覆盖**"，并写 `kMigrationMarkerKey` 标记。理由：标记保证幂等（不必每次启动重扫），
  而"补缺不覆盖"保证用户在 ini 里删掉某个键之后**不会被注册表复活**（这是真实会发生的场景：清过 `HKCU\Software\GISTool` 之后又装旧版）。
- **R-B5**：**卸载器不删 `HKCU` 设置**。`installer/installer.nsi:50-58` 只删 `HKLM` 的安装信息。
  若加 `DeleteRegKey HKCU "Software\GISTool"`，一个"装了新版但从没启动过、因此还没迁移"的用户卸载时会**永久丢失**他的最近文件列表。代价不对称，不做。
- **R-B2b（2026-10-19 计划自检新增，修的是我自己写下的计划缺陷）**：**测试代码一律不得 `qunsetenv("GIS_TOOL_SETTINGS_INI")`。**
  `tests/test_main.cpp` 在每个测试进程里都设了这个变量；一旦某个用例把它清掉再调 `appSettings()`，
  路径就变成**真人机器上的** `%LOCALAPPDATA%\GIS\GIS Tool\settings.ini`，而 `migrateLegacySettings()` 会
  `setValue(marker)` + `sync()` ⇒ **测试往用户目录写盘**，正面违反 Global Constraints 的"测试不得写真实用户状态"，
  而且这个写入还是**跨用例共享的定名文件**（批次 A 台账第 38 条记的正是这类共享状态的危害方向是假绿）。
  代价：要断"生产路径的形状"就不能构造对象 ⇒ 所以路径解析拆成**纯函数** `resolvedSettingsPath(overrideValue)`，
  测试只喂 `QString()` 断形状，**永不**触碰落盘分支。红线要写进 `app_settings.cpp` 的注释里，
  因为下一个写测试的人不会读这份计划。

- [ ] **Step 2: 写 `copyMissingKeys` 的三条失败测试**（补缺 / 不覆盖 / 幂等），先看到红

  ```cpp
  // tests/test_app_settings.cpp
  #include <gtest/gtest.h>
  #include <QSettings>
  #include <QTemporaryDir>
  #include "app_settings.h"   // src/gui 已在 gis_tests 的 include path 上（tests/CMakeLists.txt 现有写法）

  namespace {
  QSettings makeIni(const QTemporaryDir& dir, const QString& name,
                    std::initializer_list<std::pair<const char*, const char*>> kv) {
      QSettings s(dir.filePath(name), QSettings::IniFormat);
      for (const auto& [k, v] : kv) s.setValue(QString::fromUtf8(k), QString::fromUtf8(v));
      s.sync();
      return s;
  }
  } // namespace

  TEST(AppSettingsMigration, CopiesOnlyMissingKeys) {
      QTemporaryDir dir;
      ASSERT_TRUE(dir.isValid());
      auto from = makeIni(dir, "legacy.ini", {{"paths/lastInputDir", "L:/in"}, {"recent/files", "a.tif"}});
      auto to   = makeIni(dir, "target.ini", {{"paths/lastInputDir", "M:/keepme"}});
      const int copied = gis::gui::copyMissingKeys(from, to);
      to.sync();
      EXPECT_EQ(copied, 1);
      EXPECT_EQ(to.value("paths/lastInputDir").toString(), "M:/keepme") << "已有键必须不被覆盖（R-B4）";
      EXPECT_EQ(to.value("recent/files").toString(), "a.tif");
  }

  TEST(AppSettingsMigration, IsIdempotent) {
      QTemporaryDir dir;
      ASSERT_TRUE(dir.isValid());
      auto from = makeIni(dir, "legacy.ini", {{"defaults/outputSrs", "EPSG:3857"}});
      auto to   = makeIni(dir, "target.ini", {});
      EXPECT_EQ(gis::gui::copyMissingKeys(from, to), 1);
      to.sync();
      EXPECT_EQ(gis::gui::copyMissingKeys(from, to), 0) << "第二次必须一条都不复制";
  }

  TEST(AppSettingsMigration, CopiesNestedGroupsAndStringLists) {

      ASSERT_TRUE(dir.isValid());
      {

          from.setValue("recent/files", QStringList{"a.tif", "b.tif"});
  ```
