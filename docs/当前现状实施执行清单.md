# 当前现状实施执行清单

> 编写日期：2026-05-18
> 适用范围：`GIS TOOL`
> 前置约束：仅 Windows、仅算法工作台、保留全局 `vcpkg`、单人维护优先
> 对应上位文档：`docs/基于当前现状的实施计划.md`

> **面向后续执行者：** 本清单用于把上位计划拆成可逐项落实、逐项验收的执行任务。所有任务默认遵循“范围冻结、精准修改、先验证后收口”的原则。

**目标：** 在不扩展产品边界的前提下，把当前仓库收口为稳定、可验证、可发布的 Windows 算法工作台基线。

**架构：** 先统一文档和发布口径，再收紧 GUI 主链与结果表达，随后整理测试入口和新能力定级，最后完成发布验收。整个过程不引入新的展示产品方向，不改全局依赖策略。

**技术栈：** C++、CMake、Qt、GDAL、SQLite、CTest、NSIS、全局 `vcpkg`

---

## 1. 执行规则

- 每个阶段结束前都要留下明确产出，不能只有“改过了”的口头状态。
- 每次提交只覆盖一个清晰主题，不把文档、GUI 主链、结果元数据、发布收尾混成一个大改动。
- 不处理以下范围外事项：
  - 地图展示界面
  - Linux / macOS 适配
  - `vcpkg manifest` 迁移
  - 大规模新增算法
  - 仅为了“代码更优雅”的大重构
- 如果某阶段发现新增问题，先判断它是否阻塞当前阶段验收；不阻塞则记录到后续清单，不顺手扩散。

## 10. 阻塞判断规则

以下问题视为阻塞，必须在对应阶段内处理：

- 文档描述与当前产品边界直接冲突
- GUI 主链出现明显功能回退
- 关键真实回归不稳定或结果解释不一致
- 发布前标准验证命令无法复用
- 安装产物无法正常运行

以下问题默认不阻塞当前阶段，可记入后续计划：

- 局部代码风格不一致
- 非主链性能优化
- 与当前发版无关的小型重构
- 新想法型增强需求
