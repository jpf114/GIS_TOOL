# Action 测试覆盖登记表（Task 3 建立）
# 每行：plugin,action,GOLD|PENDING[,GOLD 证据用例]
#   第 4 列只对 GOLD 行有意义，写 tests/test_plugins.cpp 里那个执行该 action 的用例名，
#   格式 Suite.Test（与 ctest 显示的用例名一致）；PENDING 行留 3 列即可。
#
# GOLD 判定标准（B8 加严，2026-10-20；不得凭名字或印象标）：CoverageMeta.GoldEvidenceIsAuditable
#   把第 4 列指向的那个 TEST/TEST_F/TEST_P 块体**先剥掉注释**（行注释与块注释；字符串字面量的内容
#   原样保留，因为动作槽的形状整个活在字符串里），再在剩下的代码上核两条：
#   （1）归属：同一个块体里既要出现 "<插件名>"，又要出现把 "<action>" 送进 ["action"] 动作槽的
#        形状 —— `x["action"] = std::string("<action>")` 或 `x["action"] = "<action>"`；
#        表驱动的用例另认 `x["action"] = 迭代变量.action`，此时该 action 必须作为 case 表项的
#        首元素出现在同一个块里（删掉那条表项 = 覆盖被偷走 = 这一行立刻变红）。
#   （2）数值断言：EXPECT_NEAR / EXPECT_FLOAT_EQ / EXPECT_DOUBLE_EQ 之一出现在**代码**里；
#        写在注释里的不算（N90：旧判据直接扫块体原文，于是留一句注释就能顶替被删掉的真断言）。
#   三者等价，都是"把数值钉住"的断言；本口径在 fix round 1 由控制器裁定把
#   EXPECT_DOUBLE_EQ 也纳入（R-F1-A），原先低报的 action 不在本轮反向扩标。
# 为什么要专门立"归属"这一条：旧判据只查 action 字符串在不在块里，而
#   `params["threshold"] = 1.0` 里的 "threshold" 是一个**参数键**，
#   于是"引用 PluginTest.MatchingChangeExecutionReportsChangedPixels 就给 processing.threshold
#   记 GOLD"这条洗白配方在旧判据下是绿的（批次 A 复审提出，B8 复跑并拦住）。
# PENDING 表示该 action 目前只有“成功 + 产物存在”级别的断言，数值正确性未被钉住。
# 证据在库内：CoverageMeta.GoldEvidenceIsAuditable 直接读第 4 列回到 tests/test_plugins.cpp
#   核对上面两条（用例存在、块体属于这一行、剥完注释后仍有数值断言），
#   所以软化或删除那条数值断言、把动作槽那行注释掉、给用例改名、或改指一个不执行该 action 的块，
#   对应 GOLD 行都会立刻变红；登记表的凭据不再依赖 gitignored 的 build/ 产物。
# 维护规则：新增 action 必须在这里加一行（CoverageMeta.EveryActionIsRegistered 会拦住漏登记，
#   也会拦住已删除 action 留下的陈旧行）；给某个 action 补上数值断言后把本行状态改成 GOLD，
#   补上第 4 列的用例名，并同步下调 CoverageMeta.PendingCountDoesNotGrow 的上限——
#   该上限只允许下降。
# 计数口径（数字**只**写在下面的计数声明行里，散文不复述，免得改一处忘一处）：
#   CoverageMeta.RegistryHeaderCountsMatchData 解析每一条 `<键> = <数字>` 声明，与数据行算出来的
#   真值逐键对撞 —— 键少一个、数错一个、形状写歪都立刻红，所以 B11 晋升/降级之后忘改头部不可能绿着过去。
#   每条声明行行尾带着它的现读命令；除 gold_rows_all_lines 以外一律先 `grep -v '^#'` 排掉注释行，
#   因为本项目真发生过"为解释判据而写的注释把数那条判据的 grep 撑大"（差一也真发生过）。
#   COUNT data_rows              = 126   # 现读：grep -v '^#' tests/action_gold_cases.txt | wc -l
#   COUNT gold_rows              = 52    # 现读：grep -v '^#' tests/action_gold_cases.txt | grep -c '[,]GOLD'
#   COUNT pending_rows           = 74    # 现读：grep -v '^#' tests/action_gold_cases.txt | grep -c '[,]PENDING'
#   COUNT gold_rows_all_lines    = 53    # 现读：grep -c '[,]GOLD' tests/action_gold_cases.txt —— 不排注释行的裸计数，比 gold_rows 多出来的那一条是本表第 2 行的格式说明（那里状态列前面正好是一个逗号），所以本表新写的注释一律用 '[:]GOLD' 这种写法避开那个字面量
#   COUNT gold_rows_table_driven = 15    # 现读：grep -v '^#' tests/action_gold_cases.txt | grep -c 'SpindexOtherIndicesExecution'
#   COUNT gold_rows_literal_slot = 37    # 现读：gold_rows 减去 gold_rows_table_driven（判据里是同一条减法）
# 生成方式：ctest -R CoverageMeta 读出运行时 action 全集并逐条核对数值断言（全集条数见 data_rows，
#   两者必须相等，由 CoverageMeta.EveryActionIsRegistered 的双向核对保证）。
