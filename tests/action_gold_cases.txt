# Action 测试覆盖登记表（Task 3 建立）
# 每行：plugin,action,GOLD|PENDING[,GOLD 证据用例]
#   第 4 列只对 GOLD 行有意义，写 tests/test_plugins.cpp 里那个执行该 action 的用例名，
#   格式 Suite.Test（与 ctest 显示的用例名一致）；PENDING 行留 3 列即可。
#
# GOLD 判定标准（不得凭名字或印象标）：tests/test_plugins.cpp 中执行该 action 的那个用例的
#   TEST/TEST_F/TEST_P 块体内，存在数值断言 EXPECT_NEAR / EXPECT_FLOAT_EQ / EXPECT_DOUBLE_EQ
#   之一（逐像元、几何量或结果元数据量），并且块体内出现该行的 action 字符串。
#   三者等价，都是"把数值钉住"的断言；本口径在 fix round 1 由控制器裁定把
#   EXPECT_DOUBLE_EQ 也纳入（R-F1-A），原先低报的 action 不在本轮反向扩标。
# PENDING 表示该 action 目前只有“成功 + 产物存在”级别的断言，数值正确性未被钉住。
# 证据在库内：CoverageMeta.GoldEvidenceIsAuditable 直接读第 4 列回到 tests/test_plugins.cpp
#   核对上面两条（用例存在、块体内有数值断言、块体内出现 action 字符串），
#   所以软化或删除那条数值断言、或把用例改名，对应 GOLD 行会立刻变红；
#   登记表的凭据不再依赖 gitignored 的 build/ 产物。
# 维护规则：新增 action 必须在这里加一行（CoverageMeta.EveryActionIsRegistered 会拦住漏登记，
#   也会拦住已删除 action 留下的陈旧行）；给某个 action 补上数值断言后把 PENDING 改成 GOLD，
#   补上第 4 列的用例名，并同步下调 CoverageMeta.PendingCountDoesNotGrow 的上限——
#   该上限只允许下降。
# 生成方式：ctest -R CoverageMeta 读出运行时 action 全集（126 个）并逐条核对数值断言；
#   下面 126 行 = GOLD 52 + PENDING 74（2026-10-15 由审查者逐条核过 52 条 GOLD）。
# 备注：georef.percentile_stretch 的证据用例名是历史遗留的 QUAC 旧称，动作本身没错
#   （块体内 params["action"] = "percentile_stretch"）；用例改名归 Task 10。
